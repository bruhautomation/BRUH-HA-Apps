# Branding

The brand sources and the rules for the marks.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

Shared brand sources live in `branding/brain/`, `branding/minecraft/` and `branding/morph/` (twelve SVGs each, plus `render.mjs`, which regenerates every PNG in the repo) and `brands/` (the four-PNG brand set per domain); cross-add-on tests live in `tests/`. **`brands/` is no longer a submission staging area** — since HA 2026.3.0 home-assistant/brands auto-closes any PR adding a new `custom_integrations/` folder. Artwork reaches the integration page through a **`brand/` folder beside the manifest** (`custom_components/<domain>/brand/`), which HA serves itself and prefers over the CDN; both integrations ship one, and both deploy by recursive copy so nothing extra packages it. The `brand/` folder is what HA reads — a bare `custom_components/<domain>/icon.png` is read by nothing, which is why that file is gone. `render.mjs` writes `brand/` and `brands/` from the same SVGs and they are byte-identical on purpose: which route resolves first is not ours to control, so neither may drift. Both are the brands spec, which is why their logos are 341×256 / 682×512 and the add-on store's are 512×384 — brands caps a logo's shortest side at 256. Both marks are the same lockup — the parent's BR ligature, and a gable that doubles as the `A` — and what tells the two apps apart is how the roof and the small caps are *drawn*: brAIn keeps the parent's smooth gable, sets `AIN` smooth, and carries its signal rules; BRUH Minecraft steps the same roof onto a 16u block grid, sets `MC` on it, and drops the signal so the blocks carry it. The two roofs are deliberately different paths — a lockup with blocky caps under a smooth roof is two drawings, and `test_each_app_draws_only_its_own_roof` is what stops one app wearing the other's. Never redraw either, and never recolour the roof away from azure. **Nothing ships the gable on its own** — not an add-on icon, not a favicon, not a panel header. The roof is the family mark; it says BRUH and says nothing about which add-on you are looking at, so two add-ons wearing it in the same sidebar are two add-ons nobody can tell apart. That is what the square lockups are for, and `test_no_asset_is_the_gable_alone` is what keeps it true. The panel's top bar carries the full wordmark inline, split into `.wm-ink` / `.wm-roof` / `.wm-ai` / `.wm-signal` so one file serves a light and a dark bar.
