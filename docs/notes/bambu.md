# BRUH Bambu Studio specifics

The full Bambu entry: design with brAIn, printing, profiles, the slicer CLI, camera, thumbnails, the 3D view, failure detection.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

- **BRUH Bambu Studio** (`bruh-bambu-studio/`) - Bambu Studio (Bambu Lab's own AppImage, downloaded on first start into `/data` and EXTRACTED, never FUSE-mounted) on an Xvfb screen served in the sidebar through noVNC, with the panel bridging noVNC's websocket to a loopback-only x11vnc (`panel/vnc_bridge.py`); and Bambu Lab printers driven over LAN MQTT (8883) and implicit FTPS (990) by the panel, which is their one owner (`panel/bambu/`). Debian base and **amd64 only**, because the AppImage is glibc and x86-64. A print is a job (slice through Bambu Studio's own CLI if the file has no `Metadata/plate_N.gcode`, upload, `project_file`); access codes live in `/data/secrets` and out of backups. Integration domain: `bruh_bambu`; brAIn drives it with `bambu_status`/`bambu_print`/`bambu_control`/`bambu_slice`/`bambu_design`; voice may design a part and start a print (a file, never a url), and may not stop a print, slice, send G-code, open Bambu Studio or import a link. **Design with brAIn is reachable from Home Assistant** through three response-only services over the Design tab's own routes (`design_part` starts a part or its next message and answers once the turn has started, `design_status` is `server._design_summary`, `print_part` is `start_design_print` with its refusals); a part is named by id or by name (`parts.find`), and a summary carries `problem`, never `error`, because a caller reads an `error` key as the call failing. **Design with brAIn** (`panel/design/`) is optional and appears only when brAIn's task folder exists: each turn is a `conversation` task (`read_only` tools, `--json-schema`, resumed by the part's `session_id`) whose answer carries the WHOLE design script; the panel guards it (`guard.py`, an AST allow-list), builds it in `/opt/cad`'s venv with an empty environment (`runner.py`, `cad/build.py` + `cadkit.py`), keeps it as `v<n>` under `/share/bambu/designs/<part>/`, and sends a failed build back to brAIn up to `FIX_ATTEMPTS` times (failed attempts are not versions). Printing a part flattens Bambu Studio's own profiles for the printer's model and the tray's material (`profiles.py`, chosen by each profile's own `compatible_printers`) and writes brAIn's settings over the process profile. **brAIn starts prints from the conversation**: each turn's prompt carries the live printers and AMS trays (`designer.PRINTING.context()`), and an answer's `print.go` runs the same `server.start_design_print` the dialog's Slice and print does (`DesignPrinting.start`), whose sentence lands in the conversation — the print's own note waits for the turn to end (`RECORD_WAIT_S`) or the turn's last save would lose it. A part's 3MF is ONE object with a part per body (`cad/mf3.py`), each part's filament in `Metadata/model_settings.config` — the shape Bambu Studio's importer reads for any 3MF (`bbs_3mf.cpp`), and one object so the CLI's arrange cannot pull a print-in-place part apart; `design/painting.py` rewrites those numbers to the trays chosen, one filament profile per tray, `ams_mapping` in that order. Print offers Auto print (a message asking brAIn to print), Manual print and Open in Bambu Studio. One card file (`lovelace/bruh-bambu-card.js`) defines `bruh-bambu-card` and `morph-bambu-printer`; run.sh copies it to `/config/www/bruh_bambu` and `/config/morph/cards` at start and every two minutes (`keep_cards_current`, only a changed file is written). **Print options are ONE table** (`design/options.py`): brAIn's schema, the panel's dialogs (`/api/print/options`), `profiles.apply` and the printer's start command all read it, and every enum value is one Bambu Studio's own key maps hold (`TestOneTableOfOptions` pins them) — an unknown value is the CLI's exit -18, whose rejected setting `slicer.rejected` now reads off the log. **A slice that fails says the CLI's own words**: "run found error, return N, exit..." is the CLI's `flush_and_exit` signing off, never the reason, so `slicer.cli_error_lines` reads the `[error]` lines before it, every code in BambuStudio.cpp's `cli_errors` table has words (`EXIT_REASONS`), and a -2 names the check it failed (`invalid_hint`). **A 2.x machine profile pulls its G-code in through `include`** (template files by name), which only Bambu Studio's GUI preset loader resolves, so `profiles.flatten` merges them itself and refuses a missing one: a profile flattened without its start G-code slices a print that never homes. **The CLI does not follow a system profile's `inherits` either**, so a bare model sliced with profiles named directly (`slicer.start`) was handed the leaf files as they are and the A1's bed size, held by its family profile, never arrived: the G-code said `printable_area = 0x0,200x0,200x200,0x200`, the part was recentred at 100,100 and anything wider was exit -50. Every profile `slicer.start` hands over is flattened now, a `machine` may name one of the house's printers (`slicer.machine_named`: by its name, serial or id, and the profile comes from its stored MODEL, never the words in its name), and `profiles.machine_profile` refuses, naming the printer, a machine whose chain gives no `printable_area`/`printable_height` rather than let the CLI slice on its default (`tests/test_bambu_bed_size.py`, whose stand-in CLI reads each file without its parent). A COMBINATION can be refused too (100 % infill in a pattern that is not a `top_surface_pattern` value, a spiral vase with walls, infill, a top or supports — `validate()` in PrintConfig.cpp), so `options.reconcile` runs over the FINAL process, the profile's own defaults included, and its sentences reach the conversation (`prepared['adjusted']`). **Open in Bambu Studio opens a copy carrying `Metadata/project_settings.config`** (`profiles.project_settings`, `painting.with_project`, `server._studio_copy`): without a config whose `printer_model` is a Bambu Lab machine the GUI loads a 3MF as geometry only under *The 3mf file has invalid config* (Plater.cpp `is_bbl_vendor_config`). Camera frames load into a second picture behind the one on screen and the two swap once it is decoded (`cameraNode`'s `back` buffer): a `src` swap on the visible picture blanked it every frame, even with the URL already decoded elsewhere, and brAIn's replies are drawn as Markdown by DOM nodes, never innerHTML. **A camera frame is a whole picture or it is not kept** (`camera.whole` / `fit`): a frame without its end marker decoded as a green or grey band, and a 16:9 camera that says 1088 rows is told 1080 so the decoder crops its padding rows (a green bar along the bottom); the picture box takes the decoded frame's own aspect ratio, and nothing but controls is drawn over it (a progress line along its bottom read as a green bar in the feed). **A printer's file pictures are read one at a time per printer** (`thumbs._printer_lock`): a list asked for every picture at once, the printer's FTPS serves one session well, and each failure became a "3MF" tile for good. A short block is a read error (`RemoteFile._block`), the answer to a cut transfer is waited for `ANSWER_WAIT` and the session reopened if it never comes, the cache is generation `printer2` so an older release's false "none" is not trusted, and the panel fetches each picture, retries a failure and shows a quiet plate for a file that truly has none. **The 3D view is a turntable with Fusion 360's map** (`viewer.FusionCamera`, OrbitControls is no longer used): Z up and elevation clamped short of the poles, left or Shift+middle drag turns about the point grabbed, middle or right drag slides, the wheel and a pinch zoom toward the point under the pointer (a homothety about it, so it stays put), and Home/named views move there and frame the box; `cameraState`/`pointAt`/`screenOf`/`boxOnScreen`/`settled` are what `measure-bambu-design` reads it back with. A vertical drag moves the view with the hand (down lowers it; `invertY`, the **?**'s *Invert vertical drag*, in `localStorage` `bambu.invertY`). **Measure snaps like Fusion's** (`Viewer._snap`): vertex > edge midpoint > flat-face centre > edge > face, within 12 px (22 on touch), over each body's feature edges and flat regions worked out once (`_prepare`, regions grown lazily) and only where nothing of the part is in front (`_visible`); the distance is a DOM label on the line, the ΔX/ΔY/ΔZ legs are dashed, a face gives a perpendicular and two faces or edges an angle (`_result`), `snapAt`/`measureState` read it back. **A body's colour is chosen from its pill's dot** and stored on the part (`parts.set_body_colour`, `{colour, over}`): it wins over COLORS wherever `server._body_colours` is read (the tray offered, a print with no tray named, Open in Bambu Studio), brAIn's next prompt names it, and `settle_body_colours` drops it once a build writes another colour for that body. The pills, the measurements and the colour choice live inside `#viewerWrap`, so full screen keeps them. **An AMS Lite has no humidity or temperature** (`protocol.ams_lite_only`, A1 and A1 mini by model or serial prefix, or a report that names its AMS a Lite): the report's number for it is not a reading and reached the panel, Home Assistant and brAIn as one. **The camera** (`bambu/camera.py`) is opened on demand and closed `IDLE_S` after nobody looks: P1/A1 JPEG frames on 6000 (an 80-byte auth packet, then length-prefixed frames), X1/P2S/H2 RTSPS on 322 through ffmpeg; Home Assistant's `camera` entity asks by touching `/config/.bruh_bambu/camera/<id>.want` and reads `<id>.jpg`, because there is no port between Core and the add-on. Pictures (`thumbs.py`) come out of the 3MF, from `cad/thumb.py` (painter's algorithm, CAD venv) for a mesh, or from a file on the printer read in place with `ftps.RemoteFile` (REST ranges; a read error is raised, never cached as "no picture"). **The integration is set up by the panel** (`ha_setup.py`): Core loads a custom integration only at start, so the panel starts the config flow through the Supervisor's Core proxy once Core knows the handler, and otherwise says a restart is owed (Printers tab, one notification per version) and offers `homeassistant.restart` as a press; `integration.json` is how it reads which copy Core runs. **Print failure detection** (`panel/watch/`, a switch per printer on the Printers tab, off by default) spends brAIn looks where prints fail and nowhere else: `plan.py` reads the print's own `plate_N.gcode` once (from the library, or off the printer through `ftps.RemoteFile`) into per-layer footprint on a 2 mm grid (prime tower, purge line and skirt left out), features and minutes left, turns the first layer, a few mm up, a sharp narrowing, bridges/overhangs/supports, a colour change, tall-for-its-base and the last layers into weighted candidates, and chooses them under a per-print budget (`BUDGETS`) with a minimum gap, a candidate too close to a later chosen look riding along as `also`, one routine look per long quiet stretch; a file it cannot read is `estimated` from the layer count. `vision.py` is free and runs every frame (ffmpeg to a 48×36 grey grid): a covered lens (flat, or black with the light on) or a dark chamber stands every look down, identical frames are a frozen feed, a per-pixel median of five frames takes the toolhead out and a jump far beyond the print's own spread of changes asks for a look now, and the plate seen before the first layer is what "plate clear" compares a finished plate against. A look is `judge.py`'s: the frame, the plate's own picture and the previous look's frame handed to brAIn as PICTURES (a `read_only` task with `images`, which brAIn's listener turns into image blocks — the run can see them and open nothing), a checked verdict, and `decide` turning it into ok / watch (look again, tell nobody) / warning (notify, Ignore or Pause) / failure (pause, notify, Resume or Stop) by sensitivity, mode and what the owner already said this print (`ignored`, `no_pause`). A pause is sent outside the watcher's lock, because a command waits seconds for its echo and the panel's state is read under that lock. The integration's `alerts.py` delivers: a persistent notification, a `bruh_bambu_print_alert` event and, to the notify service chosen on the panel, a phone message with the Last print check camera as its picture and buttons that come back as `print_alert_action` naming the alert. Experimental.

- **The plate watch runs without failure detection, and only after a finish** (`PrinterWatch._plate_only_step`; `Watcher.wanted` starts a printer's thread for detection OR the plate setting, which defaults on). With detection off the camera is never touched while a print runs: a finish (or a printer found finished, plate `unknown`) makes the plate `occupied`, and a frame every `SAMPLE_PLATE_S` is compared with the empty plate for `PLATE_WATCH_S`. **A cleared plate teaches the empty plate**: brAIn's `empty` keeps the frame it judged, and a person's *Plate is clear* fetches a fresh frame in a thread (`_learn_empty`) — the frame from before they pressed may still show the part — so the next finish clears for free. The panel reads `failure_detection.plate` even when detection is off: a finish whose plate is `clear` draws no job and says *Ready* (`plateClear` in app.js). `_look` and `_record_look` handle a plate look with no print record, because with detection off there is none.
- **A look is the sharpest of a burst** (`_steadiest`, `BURST_FRAMES` × `BURST_GAP_S`, `vision.sharpest`, the edge over the plate rows): an A1's bed slides and every bed drops at a layer change, so the newest frame was often a smear. It runs in the look's thread, outside the lock, through `owner.sleep` so a test does not wait. Plate looks skip it (the toolhead is parked). The judge prompt says a smear or a moved plate is not a failure.
- **Settings › brAIn is `prefs.py`** (`/data/preferences.json`): `design_model` and `look_model` are one of `prefs.MODELS` and nothing else, because brAIn's listener puts a task's `model` on the CLI's command line unquoted; `brain_link.submit(model=)` leaves the key out for `default`. The owner's `design_notes` and `print_notes` reach every design turn after the brief (`designer.owner_notes`), framed as defaults the person's words override. Read on every turn: no restart.
- **The printer's storage is sorted newest first on the server** (`ftps.listing_time` turns a LIST date into a timestamp, a time-without-year in the future being last year), and the card draws it as a list without pictures (the printers' FTPS rarely served them). The date is shown in UTC because it is the printer's own wall clock.
- **The panel's layout rules** (`style.css`): one header row at every width (`--bar-h`, the brand hidden under 640px, the tabs icon-over-label); on a phone the Design part view is `100dvh` tall and the page does not scroll — **the stage must not be a scroll container**, because a vertical one-finger drag on the 3D view was taken by it as a scroll and never turned the view (the measure's "one finger down" check); a floating toolbar over the view's bottom edge was tried and dropped, because it covered the picks there. Hover styles are inside `@media (hover: hover)`, or a phone keeps the last tapped tab grey. `.optgrid > label > input { width: 100% }` needs its `label.check` exception, or a checkbox is stretched to the column and the dialog scrolls sideways. In the measures, **every check that reads a size runs before any full-page screenshot**: after one, Playwright measured the page as if `pointer: coarse` no longer matched and every button came out 38px.
- **Anything the panel redraws on its poll must be a node that outlives the redraw if it holds state a person set.** The ⓘ on failure detection was built inside `printerCard`, so every four-second `renderPrinters` replaced it with a closed one, which read as "it closes by itself"; it is now one `details` per printer (`infoNodes`, like `cams` and `storageNodes`), moved into each new card. An ⓘ is not closed by an outside click (a ⋯ menu is); its ✕, the ⓘ or Escape close it. Under 640px it is `position: fixed` inside the screen, because an absolute popup anchored at the ⓘ ran off the left edge.
- **The Design stage on a phone is a budget.** The version is one `details` line (`#partInfo`, its state in `localStorage` `bambu.partInfo`) instead of the summary, warnings and dimensions spread under the view; the body pills are moved into `.viewtools` under 900px (`placeBodies`, a `matchMedia` listener), and the row wraps in full screen so no pill is scrolled off; the view is `36dvh`. The measure holds the conversation to at least a third of a 390×844 screen and the ? help to fit the view without scrolling (it is 13px there for that).
