# brAIn: the findings store and its endings

What a finding is, how it ends (Wrong, done, To Do, mute), the settled ledger, folding and dedupe, corrections and their scope, the interpreter, the decision trail.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

What each rule cost to learn is in `docs/notes/history/findings.md`.

## What a finding is

- **Three kinds of knowledge, and they don't mix.** Memory = what is *true* of the home. A hypothesis = what brAIn might have *wrong*. A **finding** (`panel/findings_store.py`) = what is *broken*. The generation contract keeps them apart too: `learned` feeds memory, `findings` feeds the work list.
- **Three kinds of knowledge, one list of decisions.** Hypotheses and findings stay in different stores but are the same *job* — a question only the person living there can answer — and that job has exactly one surface: the Findings tab.
  - Open hypotheses ride down `/api/findings` (`server._findings_payload`) and `open` spans both, because "how much is waiting on me" is the only question a badge on a work list answers.
  - `questions` is gone from the stored card, the `/api/questions*` routes are gone with it, and the Memory tab has no badge: a badge counting work nobody has to do is how the badge next to it stops being read.

## Ending a finding

- **A finding leaves the list when a person ends it, and then it is gone.** Four presses end one — "I've fixed it", "Wrong", "Got it" after an automated fix, and "＋ To-do" (which defers the memory line, below) — and each does the same three things: a plain line into `memory.md` (phrased per ending, because they are different facts), a normalised key into the settled ledger (`findings-settled.json`), and the row deleted. There is no archive of dismissed cards: memory is the record.
  - **The ledger is an index, not a queue** — same rule as the facts ledger. `add`/`add_many`/`is_known` all consult it, because settling deletes the row and deduping against the list alone would turn every ending into a Forget.
  - `unsettle` is the one thing that removes an entry, and only because a person pressed "Let brAIn raise it again" — which stops the suppression and nothing more, so nothing "comes back" unless the next analysis finds it still there. A button that exists only in prose is a button nobody can press.
  - The no-archive rule is **narrowed to the invariants that made an archive bad** (`test_there_is_no_archive_of_dismissed_cards`): an **Answered** filter whose `match` returns false for every live row, **counted so it can hide at zero**, **capped** in what it renders, **absent from the badge**, and carrying exactly **one verb** — never a restore, a reopen or a route back into `/api/finding/`. A per-status `ignored`/`fixed`/`Everything` chip is still refused.
  - `fixed` is *live*: brAIn changed something in the house and news nobody has read is not settled. Dismissals from before the ledger are folded in at startup by `migrate_settled()`.
- **A button that ends a finding has to be able to say why, and the why is the half that teaches.** A key in the settled ledger suppresses one wording while the next run makes the same mistake in new words.
  - `✕ Wrong` is the ending with a `note` (`POST /api/finding/{ts}/wrong`, `/ignore` kept routed for a panel served before the update); `hypothesis/{ts}/reject` and `done` take the same note. `source` is per-verb, not "a note means a correction": a Wrong is evidence brAIn misread the house, a note on `done` is more of the fact being recorded.
  - The note goes two places and **neither is a rule**: `findings_store.prompt_block` renders it verbatim as `They said: …` under the finding it corrects, and it is queued to the memory inbox with `source="correction"`, where the consolidator records the standing truth the reason implies, or nothing if there isn't one — never whatever was typed.
  - **The box is never required**: a mandatory field turns a one-press dismissal into a chore. A note on an ending with no `noted` template (`done`) falls through to the ordinary memory line.
  - The reason box opens in place of the card's buttons, inside the card, so the thing being corrected stays on screen. The chat strip's `✕ Wrong` opens the same box; `setChatFinding` clears it, because the strip is one reused element.
- **"Check again" is the one press on a finding that says nothing about the house** (`h_finding_recheck`). A check reads one instant, so a state that simply went away needs neither "fixed" nor "Wrong". The three rules are `clear_resolved`'s, reached by a press rather than a timer:
  - **Only a check may be re-run** — an analyst finding came from a Claude run over a whole category (that is Regenerate on the card), so the button is absent there rather than failing.
  - **A check that could not look clears nothing**, and the skip or the exception is named.
  - **The whole check clears, not the row** — a re-run that finds two of its three rows gone clears both.
  - It settles nothing and writes no ledger entry: a problem that went away on its own is not a fact about the house.
- **Only Wrong is permanent in the settled ledger, and a right answer lapses when its evidence does** (`findings_store.lapse_settled` / `FIXED_LAPSE_DAYS`). Wrong is a statement about the house; "I've fixed it" is a statement about one afternoon.
  - A `fixed`/`accepted` key from a `check:` source lapses when a pass of **that check** runs and does not report it (read the way `clear_resolved` reads it, so a skipped check lapses nothing); any other `fixed` lapses after ninety days, because nothing re-runs a model's judgement.
  - A recurrence files again carrying `recurred`/`previous_at`. `accepted` lapses with `fixed` because agreeing to do something is not evidence it stopped being true.
- **"I've fixed it" on a check's row is checked by that check** (`findings_store._hand_fixes_came_back`, in `clear_resolved` after the chores). Still reported by a pass that ran, past `todo_store.CHORE_SETTLE_S`, the answer lapses (`came_back_at`) and the next pass files the row again as a recurrence through `triage.gate`; nothing is filed from the store. Never Wrong, never an `accepted` chore.
- **A fix that has run is read by what it concluded, not by the row's own claim** (`cases._from_finding` carries `result`/`changed`; `answers.situation` reads `finding_status`).
  - `fixable` is the rule's guess from before anybody looked.
  - `needs_you` is the fixer saying a person has to do this. Leading with *Fix it* there bought another plan run to reach the same conclusion, so it renders as a pair of hands. It keeps the check's own situation where that already was one, because that situation decides the reason the box opens with.
  - `failed` is `fix_failed`. Trying again is a fair press, but it sits behind the ⋯, because the failure is what should be read first.
  - The card shows the report in place of "How brAIn would fix it", which on a finished fix described a plan that is over.

## To Do: the accepted ending

- **A finding you have accepted is not a decision any more** (`panel/todo_store.py` + `findings_store.SETTLE_KINDS`). The Findings tab is a list of DECISIONS; "yes, that is real, and I will do it" needs somewhere to go.
  - **＋ To-do is the fourth ending**: the row deleted, the key settled, and **It writes NO memory line** — the fact is written when the chore is ticked off, in exactly the sentence `done` would have used.
  - `accepted` is its own settlement kind: the scorecard counts it as **confirmed**, and completing the chore re-settles the *same key* as `fixed`. `remember_answer` is the door for that (the row is long gone), keyed on **what the item stored**, never a second derivation from a copy of the text.
  - **An item carries the finding's evidence and never a pointer to it** (text, detail, fix, entity, producer), so a hand-added item is the same kind of thing.
  - **The id is minted past what is taken** (`proposals.add`'s bug).
  - **Dropping an item undone releases the suppression** (a moved finding's key; a hand-added one has none, which is what `origin` is for): deciding not to do something is not evidence it stopped being true.
  - **Finished chores are kept, capped and counted by nothing**; the one verb is *Put it back*, which does not take the memory line with it. And **the cap refuses the add rather than making room**.
  - `h_finding_todo` creates the item **before** the row is deleted and refuses the whole press if it cannot. `_complete_todo` is lifted out of the route because the tab's Done and a tick in the To-do app are two doors on one answer.
- **A chore is a decision already made, so it is not in the queue** (`cases.FEED_KINDS`). `list_cases` defaults to every kind but `chore` and `open_count` follows. A default, not a removal: a chore is still a case (`get` answers for it, its endings ride `CASE_HOOKS`), and the Resident's "already said" prompt asks for `kinds=KINDS`.
- **A chore marked done is checked by the rule that filed it** (`todo_store.CHORE_SETTLE_S`, `server._rerun_check`). `clear_resolved` reopens a `check:` chore finished more than two hours ago whose check still reports it ("Came back: …", the ledger back to `accepted`), and `_complete_todo` schedules a re-run for the same moment (`_verify_fix`'s helper). The delayed re-run is in memory; a restart leaves it to the next scheduled pass.
- **Every finding says what To Do will say** (`findings_store.todo_text` / `todo_text_of` / `todo_parts`). The producer writes `todo_text` (and `todo_line`) only where it KNOWS the device and the job from parts — `checks.network.todo_words`, `checks.devices._battery_todo`, the Resident's `CASE_SCHEMA.todo_text` rewritten by `refine`. A row without one shows its own claim word for word, with the device's name in front when the claim does not name it.
  - **Nothing is derived from free text** (#879): `derive_todo_text` is gone, with `checks.run_all`'s call to it and `_model_findings`' filling of an empty fix from it. Stored only where written (`_case_fields`' absent-not-empty rule) and never a question (`clean_todo_text` refuses one).
  - `_move_finding_to_todo` files the item under the headline (or a resolution's `fix`), with the report as `claim`, the producer's `todo_line` and the case id as `from_case`; the memory line and the ledger entry are still about the claim.

## Folding and dedupe

- **A reworded report about the same entity from the same producer is the same report** (`findings_store` subject fold, `SUBJECT_FOLD_EXCLUDED`). Text dedupe holds for checks, whose text is stable; a model-written producer (no colon in the source) rewords every pass, so it also folds on `(entity_id, source)` against every live status and a settled `ignored`. Never a `fixed` (a fixed problem may come back), never a row with no entity, never the safety/security/correction family. Only ledger answers from 2.12 on carry `entity_id` and fold.
  - **And across model-written producers, against LIVE rows only** (`CROSS_FOLD_STATUSES` / `CROSS_FOLD_EXCLUDED` / `_cross_folds`): a model-written report about an entity with an `open`/`triaging`/`held`/`needs_you` model-written row folds into it whichever producer wrote it; the newer `detail` replaces the old, status and verdict stand (so a held row absorbs every re-report).
  - Narrower on purpose: never against a `fixed` row, never against the settled ledger (a Wrong was said to one producer about its claim), never the Resident in either direction (a case refines the row it was sent to).
- **A question about an entity a check already reported folds into the check's row** (`findings_store.ASKED_SOURCE_RE` / `_check_host_key` / `_fill`). An asked card (`custom-<id>`) or the chat folds into a live `check:` row on the entity; the check's text and detail stand, the asked report fills only what the row lacks. Only asked producers (`test_cross_producer_fold`). Never into a `fixed`, `sec.*` or safety row, never from the Resident or the safety/security/correction family.
- **One device's link trouble and what it causes are one row** (`findings_store.is_link_report` / `is_link_symptom` / `WEAK_LINK_CHECKS` / `LINK_SYMPTOM_CHECKS` / `SAME_LINK`, inside `_fold_devices`; `tests/test_one_cause_one_row.py`, #582). A battery-low or gone-quiet row (`dev.battery_low`, or a model row about battery, stale or late readings) is keyed on its device, sorts after every link row, and folds into a live link row whose devices hold it, as evidence prefixed "Likely the same link trouble:". A symptom row never hosts; `_may_fold_away`'s refusals hold (a safety or security row never folds). A check's battery row is re-filed and re-folded every pass.
- **A model's link never moves a row under another card** (#792). A floor over what a model links is a name gate in another form. The first look's `same_as` stays only as a cross-reference: kept when it names a card the owner can see, otherwise the look's sentence about that card is dropped (`findings_store._visible_card` in `record_triage`); the row is held like any not-news row and never folded.
- **A row is read against the house just before it is shown** (`findings_store.LIVE_STATES` / `note_state` / `seed_states` / `holds_now`, read by `listing` and `cases._all_cases`; `tests/test_finding_holds_now.py`, #722). The checks pass seeds every state it read and the bus keeps them current; a row `_sweepable` reads (never a house check, never the harm family) that reports something down is not shown while every entity it names reports a real state that changed after the filing. "unplugged" is in `OFFLINE_RE`. The store's sweep (after `RETURN_SETTLE_S`) still ends it; a device that drops again is shown again.
- **Gone is not down: a claim that a device is unplugged is read against the registry too** (`findings_store.LIVE_REGISTRY` / `seed_registry` / `gone_now` / `as_now`, read by `listing` and `cases._all_cases`; `sre.gone_targets` / `gone_name`, `sre.answered_down`; `tests/test_unplugged_claim_read_again.py`, #789).
  - The overnight check names an entity in neither states nor registry as gone: "… no longer exists and 2 scenes still use it", step "take it out of …", never "bring it back online"; its name is the words of its id, never the id.
  - A stored row whose every named entity is now in neither is shown with that claim and step (the stored row and its key are untouched; an unread registry proves nothing), and a Wrong on such a card holds while the entity stays gone.

## Muting a rule

- **A rule wrong about this house is muted at the DOOR, and the press clears what it already filed** (`settings_store.muted_sources` / `triage.gate(rows, muted)` / `findings_store.clear_source` / `server._mute_source`). Wrong settles one *wording*; "Stop raising these" is the press for the rule.
  - **The rows are dropped in `gate` and nowhere else**, the one door every producer files through, so a mute never enters `LIVE_STATUSES`, the mirror, the badge or a dedupe. `gate` reads the setting itself when not handed one, and an unreadable settings file mutes **nothing** — the direction in which being wrong shows a card.
  - **The press clears and the gate prevents**: `clear_source` takes the producer's `open`/`triaging`/`held`/`needs_you` rows, never `fixing` or `fixed`, settles nothing and writes no memory line (a mute is about the RULE, not the house). Unmuting brings nothing back until the producer reports it again.
  - And **a muted producer is named by its own title** (off `checks.get_check`, never the group's `Device check`); `_mute_source` reads a non-check producer's title *before* clearing, and `_muted_rows` falls back through the category, the ledger, that stash and the id. The mute route's flag is `ok` because `muted` is the payload's list.
- **"What you'd need to do" has a second author** (`findings_store.set_fix` / `fix_by` / the `advice` resolution kind). The chat's `offer_resolutions` may carry `advice`; its press (`POST /api/finding/{ts}/advice`) puts the sentence on the card and settles nothing — NOT in `FINDING_VERBS`, its own route ahead of the `{verb}` catch-all, no undo token, the store's `MAX_FIX` cap rather than a button's ninety characters. `fix_by` is on the ROW (`""`/`triage`/`chat`) and the card says whose sentence it is.
- **Two read-only tools read the panel** (`get_findings`, `get_health`, over `_panel_get`, `explain_change`'s arrangement). Both trim a page of JSON to what a model can act on, neither settles anything, and they are on `ANALYST_TOOLS`, because asking whether the house already knows about a problem is exactly the read an unattended run should make.
- **And a notification opens the panel** (`notify_router.open_link` / `addon_options.panel_path`): a relative path as `url` (iOS) and `clickAction` (Android), gated the way the buttons are (`can_answer`), the path being the Supervisor's own `slug` under `/hassio/ingress/` read off `/addons/self/info` — no slug is no link, never a guess.
- **A rule the scorecard says is wrong here is OFFERED for muting, never muted** (`panel/mute_offer.py` / `server._mute_offer_pass` / `_end_mute_offer`).
  - A producer with at least `MIN_ENDINGS` endings, `MIN_WRONG_SHARE` of them Wrong and its latest ending a Wrong (`scorecard()`'s `last`) gets ONE question through `add_case` on `_checks_loop`'s tick (own stamp, no new timer, free, no gate). Yes is `_mute_source`; No is remembered with the record it was declined at and re-asked only when the Wrongs double.
  - The ending is intercepted in `_end_finding` (`notify_learn`'s pattern), writes no memory line, and Undo of a Yes unmutes. `cases.UNMUTABLE_SOURCES`, producers already muted and the question-asking producers are never offered.
  - The question says what kind of report the rule files (the scorecard row's newest `example`) and where to undo a Yes in the panel's own words — History › Ignored › Restore on "Everything like this" (`mute_offer.WHERE_TO_RESTORE`) — never "the scorecard" (#439).
  - `auto.conflict`'s `except_evidence` already covers a pair with a NEW partner (`should_report` is asked of both rules; `test_checks_wrong_in_the_field`).
- **A rule has one name** (`findings_store._check_title` / `_rule_titled`): the scorecard and `source_titles` name a check by its catalog title, as the card's `_producer_label` does, so card, scorecard, fault list, mute question and History agree. The stored `source_title` and the mirror's copy are untouched, and no two checks share a title (`test_one_name_per_rule`).

## Holding a rule by its record

- **Every rule held by its record says so, and is raised once per thing** (#1477; `rule_record.held_words`, `server._score_words`' `held_back`, `get_health`'s `rules_held_back`, `checks._util.House._once_while_held`). The gate's hold was already generic; what was not: ⚙ › Diagnostics said a hold only for brAIn's own reports, and only the reading checks raised each sensor once while held. Now every quietable check whose record `holds` gets the health line, and while it holds one Wrong about an entity closes the check for it — and for a `DEVICE_QUIET` check one Wrong about any entity of the device, so a dead device is not asked about per sensor. A check about a measurement that differs per entity is never closed by a sibling's answer; a check with no held record files exactly as before.

- **A rule three Wrongs deep is held by default until fresh evidence** (`findings_store.scorecard`'s `streak`, `rule_record.holds` / `HOLD_STREAK` / `held_reason` / `never_held`, `triage.gate(held=)` / `_record_held` / `waiting_too_long`, the row's `record_hold`, `findings_store.record_triage`, `server._resident_apply`'s fallback; #698, #500, #501, #599, #579).
  - The scorecard counts a `streak` — the latest answers about a rule, newest first, while they are Wrong (a key answered Wrong again counts each time). A rule (a house check, or a card somebody made, `user-…`) at `HOLD_STREAK` (3) has its rows filed by `gate` carrying the record (`record_hold`).
  - The look is told the streak and that only fresh, specific evidence keeps one. A row the look lets go is held as before; a row no look answers for (reply skipped it, look failed, stale sweep) is held with the record as its reason and not shown while it waits (`waiting_too_long`).
  - Held means kept: the next pass dedupes against it, it clears as any row does, History › Set aside by brAIn puts it back in one press, and nothing is sent.
  - **Fresh evidence** is a look that keeps the row, or what `refresh_details` treats as new for a held row (a higher severity, a detail naming something new); an agreement with any of the rule's reports ends the streak.
  - Never held: a critical row, a row flagged safety, protected or hot, a security or harm check, every producer `quietable` refuses, and a row about a protected entity (`rule_record.never_held`, matched on the row's own entity and items with `automation_writer.is_protected` over `protected_patterns`; an unreadable list holds nothing). `server._resident_apply`'s fallback reads the same floor again on the signal (`resident.never_ignore`), which carries `hot`.
  - Not hidden for ever where no look runs (`triage.LAST_LOOK_AT`, `RESIDENT_STATE["last_look_at"]`): with no look since it started waiting it is shown after the ordinary wait.
  - `auto.conflict`'s per-pair exception is unchanged: an answered pair is not reported at all, and a new pair from a rule three deep is held unless a look keeps it. Kept in the look rather than at the door on purpose: the look is the one judge (`tests/test_rule_record.py`, `tests/test_outcomes.py`).
- **A record held by its share, and a hold you can find** (`rule_record.holds`' `HOLD_WRONG` / `HOLD_SHARE`, `held_reason`, `findings_store.record_triage`, `decision_trail.KINDS["record"]`; #811, #812, #826). A rule Wrong at least three times and three quarters of its answers, the latest a Wrong, is held too, and its reason says the count rather than a streak. A row held by its record with no look keeping it writes a `record` row on the decision trail, so `explain_decision` names the hold.

## Answers about one thing: stop watching, stop raising, stand down

- **"Stop watching <it>" is the `entity` correction scope as a press** (`answers.can_stop_watching`, `server._cannot_stop_watching` / `_stop_watching`, `POST /api/finding/{ts}/stop_watching`, `facts_store._kind_of` → `unwatched`). The second tick in Ignore's box (the thing, for every rule) beside "Ignore all like this" (the rule, for every thing).
  - Written before the Ignore, carrying the report's finding key so the Ignore's Undo takes it back; logs a line and a trail `exception` row; listed in Knowledge › Not watched (every `exception:*` row), where Watch again deletes it.
  - Never offered — and refused again at the route — on a safety, security, critical, urgent or protected row, a lock, alarm or siren, words about leaks/smoke/gas/freezing, a device with a safety class on it, or a check in `NEVER_CHECKS`.
  - **One reader answers it for every check** (`House.unwatched`, `checks._watched_only` in `run_all`): only the `*` rule (which, through `_device_rule`, reaches the device), on the entity or another of its device, under `_never_whole` and `_applies_now`. `run_all` drops any row whose every named entity (`entity_id` and `items`) is unwatched, with an `exception` trail line ("scope: … (Stop watching)") unless the check wrote one; a check naming an entity inside a row about something else asks it itself.
  - A reason typed in the box is never read into this rule: only the press writes it.
- **"Stop raising this about <it>" is the press's own rule, chosen rather than read off the words** (#1079; `server._stop_raising` / `_chosen_rules`, `POST /api/finding/{ts}/stop_raising`, the first tick in Ignore's box, offered where Stop watching is).
  - The tick writes the pair rule `exception:<check>` first (the note as its text, permanent, no reading range, the report's finding key). The Ignore that follows finds it (`_chosen_rules`) and neither snoozes (`_for_now`), writes a second rule nor starts the `correct` job: the press said the scope and the lifetime.
  - The rule is a fact (`recall`, Knowledge show it; the Ignore's Undo takes it back). Exactly the pair: a different check on the thing, and the same check on another thing, still report (one Wrong on a `DEVICE_QUIET` check still answers its family for the stretch). Without the tick the words are read as before: a Wrong on a check's row writes `exception:<check>` on its subjects unless the words typed with it read as "not now" (`corrections.puts_off`).
- **An answer about a device reaches every producer that speaks about it, and "don't remind me" said twice stands the pair down** (#1263, #1264, #1315, #1323; `server._exception_rule` / `_sre_set_aside` / `_answered_again` / `_stand_down_again` / `_count_stands_down`, `sre.digest`, `corrections.out_of_use` / `asks_cleanup` / `cleanup_edit_row`, `findings_store._wake_hold`'s `held_before`, `today._stood_down`).
  - The overnight check's row entity is chosen by code (`sre.subject_of`), so a reason that finishes the device (`gone_for_good`) writes an `exception:sre` rule on it, which `known_faulty` reads for every check (`House.settled_device`, `answered_off`); no other reason on its card writes one.
  - `digest` drops Zigbee and Z-Wave records about a device set aside (an offline or link check's answer or hold — `net.zigbee_weak` and `net.zwave_link` are in `SRE_SET_ASIDE_CHECKS` — or a device said on any card to be finished with) as it drops log lines, floors first (a safety device, its battery, the protected list are never set aside).
  - A reason whose every clause is the clean-up instruction or an out-of-use statement is the clean-up request (`asks_cleanup`); a plain out-of-use reason asks the clean-up question where automations mention the device. Its Yes also files a `cleanup` card ("Take <it> out of …", fixable): Fix it plans read-only and only Apply on that plan changes an automation, through the action gate — nothing about the gate, the protected list or an unattended run changed.
  - A row woken from a hold carries `held_before`; a second "don't remind me" on it (or on a check and entity the ledger already holds a Wrong for) writes the pair rule (`_stop_raising`'s, which refuses a safety, security or protected thing — then it is the hold it was) and settles as Wrong with `stood_down_after`; a row about no one thing settles its words. Never where no hold is given (`rule_record.quietable`, a critical row).
  - History › Ignored shows a pair stood down by its Wrongs (`STAND_DOWN_WRONGS`, the checks' `WRONG_LIMIT`, or `stood_down_after`) as ONE row, "Stood down after N Wrong answers", whose Restore releases every key and rule of the pair (`/api/findings/unsettle` takes `keys`); a pair whose floor refuses a count is never said to be stood down. `stood_down_after` is kept apart from `wrong_count`, which the scorecard reads.

## Corrections, snoozes and holds

- **A rule's identity includes which rule it is** (`fact_id(…, predicate)` for `exception:` rows). Ordinary facts hash on subject and text, because the same sentence from two writers *is* one fact; a rule is the one row where the predicate is the meaning, else two checks marked Wrong on one sensor collide. The row also carries `about` (the report) and `finding_key`, which lets "Let brAIn raise it again" find the rule without an undo token.
- **A correction has a scope and a lifetime, and the wide ones are questions** (`panel/corrections.py` / `server._scope_correction` / `House.withheld_by`). The `correct` job answers one of `SCOPES` (`entity_check` < `entity` < `check_area` < `check`) and one of `LIFETIMES`; `plan` checks it, `apply_plan` writes only one entity's reach, and a wider scope is `offer_row` — a findings-store `question` under source `correction` whose Yes alone writes the rule (`accept_offer`, `area:<id>` or `check:<id>` subject).
  - **The model never names what the rule is about**: entity, check and room come off the pressed finding.
  - **No scope covers a safety-class or protected entity** — `never_covered` at write time and `House._never_covered` at READ time (`scope_map`'s `never` table), because a room scope cannot know what was fitted there later.
  - **Every rule carries the report's `finding_key`**, so `_undo_finding` (which always calls `forget_exceptions(key)` and withdraws offers) and "Let brAIn raise it again" take back what the pass added; a pass that lands after Undo writes nothing.
  - Lifetimes are arithmetic, never the model's: a resume date, `expires` the day before it (`facts_store._expired` is `stamp < today`), a past or two-years-out date read as permanent, seasons meteorological and swapped south of the equator (latitude off `core.config`). The confirmation sentence is built by `confirmation`, never a model. The tab's press scopes asynchronously (`_start_correction`); the phone reply synchronously so it can quote what was applied.
- **"I need to fix this light" is a snooze, not a rule** (`corrections.temporary` / `temporary_days`, `server._for_now` / `_snooze_for_now` / `_for_now_routes`, `findings_store.snooze(wake=)` / `wake_returned`, Morph's `kept`).
  - A Wrong whose reason says the thing is out of use FOR NOW (being repaired, unplugged for now, "waiting on a part", "fixing it") on a check's row, a Resident case or a Morph suggestion writes no rule, no memory line and no label: the row sleeps for the period named (`TEMPORARY_DAYS`, 14, when none; at most `TEMPORARY_MAX_DAYS`), with `snooze_wake` set to its entities; its undo wakes it.
  - A reason that says it stays that way ("I won't fix it", "unless", "most of the year") is not temporary. A reply on any surface whose words are temporary is the same Wrong whatever the interpreter read, unless it asked for something else (a fix, To Do, its own time).
  - Each checks pass calls `wake_returned` with the states it read, before `clear_resolved`: a snooze whose entities all report again is over, and a Morph suggestion to remove that thing's card is dropped and published as `kept` (Morph closes it without declining; the idea may be suggested again if the thing goes for good). Morph's suggestions carry `entity_id` for this. The answer is given in words, not a new button.
  - **"Don't remind me again" about one thing is the pair rule, said back by name** (#1479; `server._asks_to_stop` / `_said_back`, `corrections.until_it_changes`, the payload's `said`, read by every Wrong toast in `app.js` and by `_reply_routes`). A timeless deferral ("don't remind me", "stop telling me about this", "it's on my list, stop reminding me") on a quietable house check's row about one thing is no longer a hold: it is the Wrong it was pressed as, so `_record_exception` writes `exception:<check>` (which `recall` shows and the device's other entities read through `_device_rule`), no memory line is filed, and the correction's second look reads its scope and lifetime. Every Wrong that wrote a rule answers with one line built by code from the rule's reach: "Got it — brAIn won't raise this about <name> again". The hold below is what is left for words that ask for it ("until it changes"), a critical row, a safety or security check, a safety-class or protected device (`never_covered`), and a row about no one thing.
  - **"Don't remind me" on a house check's card is a HOLD, not a month** (`corrections.deferral` / `held_until_changed` / `HOLD_DAYS`, `findings_store.snooze(hold=)` / `HOLD_ABSENT_S` / `_hold_absences` / `_wake_hold`, decision kind `hold`, #602, #694, #698). A static fact is the same fact next month, so a period is the wrong ending.
    - On a check's row a deferral that names no period holds the card with no clock (stamped `HOLD_DAYS` out only so every reader of `snoozed_until` keeps it away); the answer rides as `snooze_hold` (the card's "Muted until it changes — you said …", the trail's `hold` line).
    - It ends when the check's report about that thing changes: a higher severity or a detail naming something new (`refresh_details`, `names_moved`), a new item on a row about several things, the reading moving a long way (`wake_worse`: every hold with an entity carries `snooze_worse`; the battery rule keeps its level, `server._WORSE_BELOW`; otherwise a move of `WORSE_SHARE`, a quarter, and at least `WORSE_DROP`), or the report not made for `HOLD_ABSENT_S` (three days). Then the row clears and a later return is news; a woken card says which answer held it (`hold_changed_sentence`). Re-reports dedupe against the held row.
    - A deferral that names a period or a time keeps that period (`corrections.names_a_time` / `named_time_days`: "until tomorrow"/"tonight" a day, "next week" seven, a weekday or the weekend the next one, a month name the first of it, a season the day it starts — swapped south of the equator — and "later", "after the holidays", "for a while" the month; "until it changes" and "unless it gets worse" name no time).
    - On a Resident case or a Morph suggestion it is still the 30-day snooze (`DEFERRAL_DAYS`); so on a rule `rule_record.quietable` refuses and on a critical row: a hold nothing could end is not offered.
    - The words are about being reminded or told ABOUT it, never a fault statement or a request (`corrections._NOT_A_DEFERRAL_RE`); "I'm aware" followed by a fault states what is wrong and is no deferral (`_AWARE_RE` with `_FAULT_RE`), while "I'm aware …, stop reminding me" asks in as many words (`_ASKS_QUIET_RE`). A request that also says the report is wrong (`_FALSE_REPORT_RE`: "bad sensor", "false alarm", "replaced", "isn't low") is the Wrong it always was, never a hold.

## The interpreter

- **One interpreter, and no answer is the old code** (`panel/interpret.py` / `server._interpret` / `_route_ask` / `_reply_routes` / `_repairs_routes` / `_service_routes`). Four boxes take a person's words — the ask bar, a phone Reply, the Repairs reason box, `brain.intent` — and the `interpret` job (cheap tier, tool-less, `--json-schema`) maps words + SURFACE to routes out of `KINDS`.
  - **The model never names a case** — the surface stamps it and a route says only what to do with it (`ENDINGS`).
  - **A surface narrows the vocabulary** (`ALLOWED`): a route a surface cannot carry is dropped there, and a reply left with nothing is no answer.
  - **No answer is the old behaviour, exactly** — no credential, the day's runaway cap (`MAX_PER_DAY`, in memory), a failed run, an unreadable reply: `parse` returns None and the caller runs its pre-interpreter code; the regexes are the offline answer, not a second reader.
  - **Pressed surfaces skip the budget and nothing else** (`PRESSED`); `service` answers `auto_enabled` and the budget too.
  - **Nothing here adds reach**: every route lands in code that already exists (the card queue, the intent drop, `_end_finding`, `onboarding.request_study`, `_design_scenes`). One message ends a case once — a second ending in the same reply is dropped, never applied over the first. `automation_edit` is a read-only card (`AUTOMATION_EDIT_FRAME`) because no producer turns a sentence into an edit of somebody's automation.

## The decision trail

- **Why brAIn said nothing is written down by the code that chose** (`panel/decision_trail.py`, `/data/decisions.jsonl`). A closed vocabulary (`KINDS`: `cap`, `dedupe`, `exception`, `mute`, `shadow`, `no_target`, `notify_quiet`, `quiet_hold`, `gate_hold`, `look_ignore`, `look_watch`, `held`, `hold`, among others), written by the checks pass (`run_all`'s `withheld` + `pass_rows`), the notifier (`_announce_findings`) and the Resident.
  - **Nothing here decides anything.**
  - **"No record" is not "decided not to"** — `for_subject` returning nothing is the first, a row is the second, and an unreadable file is `readable: False`, a third; the explain prompt and `/api/why`'s `says` keep the three apart.
  - The file is capped by line count, never creates its own directory and never raises. Read by `GET /api/why`, the `explain_decision` MCP tool (analyst read, refused on voice) and the interpreter's explain path (`interpret.EXPLAIN_SYSTEM`, job `explain`, `run_analyst`).
- **A standing decision folds; an event is written again** (`decision_trail.FOLD_KINDS`: `dedupe`, `exception`, `mute`, `shadow`, `cap`, `hold`, among others). An identical decision inside `MERGE_S` is one row; past it a standing one folds into its row (`count`, `last_seen`; `ts` stays the first), found on disk so a restart folds too, and readers order by `last_seen`. A hold, a look's verdict and a notification decision are events and keep their line per window.

## The words on a finding

- **A finding owes its reader the effect first, the lookup done, and a step — and a reply that withdraws itself is not filed** (`prompt_kit.FINDING_VOICE` in the investigation and refine prompts, `resident.unfinished` / `triage.NOTHING_RE` in `server._resident_investigate`, `parse_first_look`, `tests/test_finding_voice.py`; #581, #603, #604, #616, #627, #618, #629).
  - A reply whose step (or, with no step, detail sentence) says "nothing is needed" files no claim, and a row brAIn filed is held with that sentence. A problem with no step, errand or action is not filed either (a high-stakes one is). A first look that keeps a row (`watch`) while saying nothing needs doing is set aside as `explained`.
  - A snake_case code name leaves the sentence for the Technical line. A step and a notification body are cut by `textclip.shorten`, never mid-sentence. The card contract has one line for a reader who saw no earlier card; its size ceiling is pinned in five tests, so a word added there is paid for by one cut.
- **A finding's words say what was measured, and a rewrite removes an aside, never a step** (`house_words.known_log_meaning`, `sre._zigbee_title` / `_zwave_title` / `_measured_title`, `findings_store.without_usual_cause` / `_look_found_cause`, `card_claims._ALL_FINE`, `tests/test_finding_words_second_look.py`; #583, #725, #726, #735, #737).
  - A log line none of the meanings reads is said as who, how often and when, with no meaning (no earlier count is kept, so there is no usual-vs-now). A mesh device's title is its record's measured state.
  - No step text is removed on a reading of the detail (steps are compound). The "(… is the usual cause)" aside goes only when the refining look cited evidence. An "All quiet" card whose every sentence is an absence is a blind lead, but never "nothing new since <date>".
  - Nothing here holds or lowers a row on its reason's prose.
- **A finding's prose names things the way a person sees them, and an id lives in its evidence** (`checks/_util.House.label` / `spoken_id` / `without_mac` / `evidence_for`, `tests/test_finding_text_plain.py`).
  - A check's `detail` and `fix` name an entity with `label` (its name, or for one with none the id read aloud: *the scene “before movie”*), a device without its MAC (one named only by its address is counted, not spelled), and a remedy as a screen or a press, never a `brain.*` service; the ids go in `evidence` (`{entity, value, when}`, under the card's closed Details), because `prettyText` cannot rescue an id the house no longer has.
  - `text` is the dedupe key and is left alone except `auto.conflict`'s fallback (the house's name before the id). `refresh_details` carries a check's reworded `fix` onto rows it already filed while `fix_by` is empty, and never overwrites a sentence a look, a chat or a person wrote.
  - The test lints every catalogued check's rows: ids of a Home Assistant domain, MACs and `brain.*` in `detail`/`fix`, and in `text` only an id the house had a name for. `reg.hardware_name` may show a MAC, because that name is the finding.
- **A finding on screen holds no developer string, and a code name is said as its words** (`house_words.lint` / `ids` / `code_words` / `said_plainly`, `findings_store.shown_words` read by `listing`, `cases._from_finding`, the Home Assistant mirror (`_publish_state`) and every notification composed from a row (`outbound`), `tests/test_finding_code_names_named.py`, `tests/test_finding_words_no_ids.py`; #774, #791).
  - A code name is the house's name for the entity whose object id it is, an aside in brackets goes, and any other is said as its own words; the token still goes to Technical.
  - The display pass, over a model-written row's text, claim, detail and fix and every look's reason, says an id by its name or as its kind ("the voice service"), takes paths and line numbers out (a look keeps a bare file name, `test_open_row_look_reason`), repairs a stored "an internal name", and drops any sentence `lint` still flags.
  - The mirror carries the same words to Repairs, To-do and the watcher; a notification's slim copy (`ts`, `text`, `severity`) is read against its stored row; `ts` stays every reader's key. A person's and the safety lane's words are never touched, and the stored row never changes.
  - A look whose duration disagrees with the row's (#771) is **not** rewritten; it is shown as written until it is fixed where the look is made.
- **A check's row reads the display pass too, so the sweep is at the shared path** (#1205; `findings_store._check_written` / `PLAIN_EXEMPT_CHECKS`, `shown_words`, `house_words.technical`).
- **A check's id is never shown, on any row whoever wrote it, nor on a look's reason or a card** (#1480; `house_words.check_ids`, read by `technical`/`lint` and by `shown_words`' last pass over every row). The shape `check:<group>.<name>` — never a list of ids — is said as "brAIn's “<name>” check", or goes as a bracketed aside, and the id goes to Technical; the id pass used to read its tail as an entity ("check:the “not reporting” action"). Fixed status lines say "brAIn's check" rather than an id (the follow-up's `reports it again`), Diagnostics' rule rows say what brAIn shows rather than that it "holds rows", and a quiet card carries `quiet_why`, its first sentence led by its verdict off its fields (`card_verdict.quiet_line`: "All fine: …", "Nothing to report: …"), which the All quiet list shows because it draws no chip; the summary is untouched, so the opened card says its verdict once, in its chip. `auto.trigger_unavailable` carries a `headline` naming the automation and the entities it saw; `text` stays the key.
  - A `check:` row's text, claim, detail and fix go through `_plainly` like a model's, what it takes out goes to Technical; `text` stays the dedupe key and a row `lint` finds nothing in comes back as it was.
  - Not read: `check:safety.*`, `check:climate.freeze`, `check:base.heater_idle`, and the sources in `PLAIN_EXEMPT` — a pass that drops a sentence must never drop a hazard's.
  - The pass also reads a relative path, a build number after a version (version stays), the service domains `python_script`/`shell_command`/`rest_command`/`ai_task`, and says brAIn's own "integration" as the link between brAIn and Home Assistant. A version number alone is still the household's word.
- **An insight card's words read the same display pass, and a build at a sentence's end is still a build** (#1313; `findings_store.plain_said`, read by `server._insights_listing` for a card's title, summary and next step; `house_words._DATE_BUILD_RE`). The card file is not touched; its entities and its finding twin are read before the pass.
- **Voice ids and date-stamped builds are developer strings too, and what the display pass takes out goes to Technical** (#1133, #1084, #1086; `house_words._VOICE_ID_RE` / `_DATE_BUILD_RE` in `technical` and `lint`, `findings_store.shown_words`' `technical`, `prompt_kit.FINDING_VOICE` (7) and in `sre.SYSTEM`, `checks/devices.restored`).
  - A voice id after "voice" goes (elsewhere "a voice"); a dated build is said as a month and year. `shown_words` returns the row's `technical` with every fragment `lint` found, so Details keeps it.
  - FINDING_VOICE is in the overnight check's (`sre`) prompt as well as the Resident's. `dev.restored` changes wording only, `text` untouched as the dedupe key.
  - A model's step keeps an IP address it acts on (`house_words.addresses(step=True)`). That address stays in the house: `devloop/plaintext.without_addresses` (IPv4 with port, IPv6, MAC, by shape) runs in `upstream.scrub`, through `screens.redact` on every picture, and on the design review's block (`streams.design_context`).
- **An id and a path are known by their shape, and every surface reads a row through one door** (`house_words._an_id` / `_id_noun` / `note_services` / `_ANY_PATH_RE`, `findings_store.shown`, read by the list, `cases`, the mirror (`_publish_state`) and `outbound`).
  - A dotted token is an id when its domain is the table's, a domain the house has services under (the last checks pass's `services`), a part is snake_case or it is in backticks; an id outside the table's domains is an action, said as "the “refresh value” action".
  - Any absolute path of two or more segments is a developer string; with no household words for it, its sentence is not shown and a step falls back to the row's To Do line (`shown_fix`), then to `TECHNICAL_STEP` (ask brAIn in the chat to take it), so a row that had a step keeps a household one. `shown` is `shown_words` plus `shown_fix`, and every surface reads it.
  - "Integration" and "registry" are reworded where they are written (the investigation, refine, `FINDING_VOICE` and card contracts; check and overnight steps), never filtered. Where a check's `text`/`detail` holds the word, the row carries `headline` / `shown_detail` in plain words (`dev.restored`, `reg.orphan_device`, `sys.entry_failed`, `integ.custom_unused`, `net.matter_empty`, the connectivity row's UniFi line, the printer-done row), which `shown_words` shows over them and the refresh copies onto an open row.
- **A finding about several things carries all of them, and its sentence is never cut inside a name** (`checks/_util.join_names(budget=)` / `LIST_BUDGET`, `findings_store.item_labels`, `cases._item_list`, `caseItemsNodes`). An inline list stops at a character budget as well as a count; `org.dashboard_dead_ref` and `auto.dead_ref` carry the whole list as `items`; a case naming two or more gets `item_labels` (each by the house's name, or the id read aloud for one that no longer exists, never the id), shown as a count line ("8 entities · Show all") over the full list. `measure-today` holds both at 390 and 1200 (#437).
- **An impossible overdue figure is asked as a setting, in words that do not hold the figure** (#1201; `findings_store.misread_reminder` / `REMINDER_MISREAD_X` / `_OVERDUE_RES` / `_INTERVAL_RES` / `_overdue`).
  - **A reminder figure past ten times its own interval is a setting, not a fact**: for a model-written row whose words or evidence state both figures in one unit it becomes a question, `kind` question, severity info — the row's own headline with the figure cut out ("Oil change reminder is far overdue. Is the reminder's setting right?"), figure and interval in the detail, so a Wrong holds by those words, for that reminder only.
  - `misread_reminder` and `odometer_counter` (#827's drop: a distance overdue with no interval is information) read one set of shapes (`_overdue`: "N miles overdue", "overdue by N miles", "due N miles ago", "a 5,000-mile interval", a negative distance-left reading, never "5 -20 miles").
  - A Wrong on "Is the reminder's setting right?" (`REMINDER_ASK`) stands down every producer's overdue row about that entity (`_reminders_answered_wrong`).

## Counts, the mirror and the scorecard

- **Findings are mirrored to the shared volume, because /data is invisible to Home Assistant.** `findings_store._write` republishes `/config/.brain/findings_state.json` on every store write — hooked there so no code path can change the store without it — and `publish_state()` re-runs it at panel startup so a boot never serves last week. The mirror is derived and never read back; the integration's `FindingsWatcher` (primed at startup, `LearningWatcher`'s no-replay contract) diffs it into `brain_finding` events, and `sensor.brain_open_findings` reads it. Skipped when the shared volume's parent does not exist (a dev checkout must not grow a stray `/config`); an OSError is a logged warning, never a lost finding — the row is already safe in /data.
  - **Notifications go to the CREATED list only** (`server._announce_findings`): `add_many` dedupes across every status and the settled ledger, so a re-report cannot ring a phone twice. The target is the `findings_notify_service` option read live from the Supervisor snapshot (run.sh env export as fallback); a failed delivery is a log line, because the finding is already on the list.
- **One source for every count, and one status line** (`cases.queue_count` / `facts_store.count` / `server._counts` / `panel/brain_status.py` / `server.publish_status` → `/config/.brain/status.json` → `custom_components/brain/status_mirror.py`).
  - **the queue** is `cases.queue_count` — open findings, open questions, open suggestions, plus a row waiting past `triage.SHOW_AFTER_S` — read by `/api/status`'s `queue_count`/`findings_open`, `/api/findings`' `open`, `/api/cases`' `open`, the mirror and `binary_sensor.brain_needs_you`.
  - **To Do** is `todo_store`'s open items (`list_count`, and `todo.brain`); **facts** are `facts_store.count` (House › What it knows' `all`, `summary()['count']`, `facts_count`, the Facts learned sensor); **run rates** divide `journal.summary`'s `claude_failed` by `claude_runs`. A store that could not be counted is `None`, never 0.
  - **The status line** is `brain_status.derive` — `signed_out` > `needs_restart` (`_integration_versions().restart_pending`) > `paused` (switched off, the account's limit with `back_at`, the budget) > `degraded` (the last health verdict, `HEALTH_CACHE`, filled wherever the diagnostics payload is built) > `watching` — `{state, label, sentence, since, back_at, last_look_at}` on `/api/status`, in the diagnostics payload and in `status.json`, rewritten every scheduler tick and at startup.
  - `sensor.brain_status`, `binary_sensor.brain_needs_you` (on the brAIn System device; the old *Waiting on you* is *Questions waiting*, unique id kept) and the facts sensor read only that file: missing, garbage or older than its `stale_after_s` is `unknown` with a `reason` — never `off`, never 0, never the last answer.
  - Server-composed numbers go through `numfmt` (rounded by size, a real minus, the unit spaced) and display prose through `textclip.clip`; no check's sentence says "press Wrong" (`tests/test_numbers_agree.py`).
- **The producer scorecard needs the producer on the settled entry.** `_remember_settled` records `source`/`source_title`, `findings_store.scorecard()` aggregates ("I did it"/"Got it" right, "Wrong" not), and it rides `_findings_payload`. The tab shows a producer only past `SCORE_MIN_ENDINGS`. A pre-1.29 ledger entry has no source and scores nothing rather than everything.
- **Every ending says the release it was given under, and an old one is `unknown`, never now** (`findings_store.current_release` / `release_of` / `UNKNOWN_RELEASE`, `scorecard(release=…)`, `scorecard_by_release()`; `tests/test_findings_release.py`).
  - `_remember_settled` writes `release` (`ADDON_VERSION`, read at call time) on every new ledger row, `settle_and_clear` returns it, and every scorecard row says the release it was counted over (`None` for all).
  - A row with no release (from before the field, `migrate_settled`'s `release=""`, an import) counts under `unknown` — never the running release.
  - `scorecard_by_release()` is the devloop canary's query: `{release: {producer: {"right", "wrong", "total"}}}`; right is every ending that is not Wrong and "Doesn't apply" counts nowhere.
