# brAIn: memory, facts, guesses and curiosity

memory.md and its one writer (the consolidator), the inbox, the facts store and its reconcile, hypotheses, curiosity, occasions, the memory extractor hook, study sessions and memory clean-up.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

- **Memory**: `memory.md` is the only thing that is "memory". The inbox, the hypothesis queue, and the change log are queues and audit trails, and are never injected into prompts. Every writer goes through the inbox — nothing writes `memory.md` except the consolidator. `POST /api/memory/consolidate` runs the same consolidator with `--once`; it does not become a second writer (the panel's "File into memory now" press was cut by the redesign, ⚠3 — the queue files itself). **The facts ledger (`knowledge_store`) is a dedup index, not a queue** — nothing may be deleted from it, or the analyst re-announces what you have already seen, and it is emphatically not what the Memory tab lists (the tab reads the inbox itself — `server._inbox_items`; see the bullet on the queue's list and its count). **Filed discoveries are not rendered anywhere** — once something is in the document, the document is the one place it is read and edited; listing them again under "already in memory" left a permanent list beside a queue that was meant to read as empty. The ledger still holds them, so nothing is re-announced. Never report a consolidation by the count you asked it to file; read the queue either side of it (a pass can exit 0 and keep the facts, and exit 75 when another pass holds the lock).
- **A lock file's existence is not a lock, and its mtime is not an age.** `with_lock` takes `/config/.brain/memory/.consolidate.lock` with `exec 9>` and releases it with `exec 9>&-` — which drops the flock and leaves the file on disk for good, so the file says only that a pass has run at some point and its mtime says when the last one *started*. `ha-selftest.sh` (`brain doctor`) stat-ed that mtime and warned past 900s, which fires on every home that has not consolidated in the last quarter of an hour: a permanent warning about a memory system that was working, on a report whose whole value is that its lines mean something. The remedy it named could not clear it either — the file is under `/config` and survives the restart it asked for. The panel had it right from the start (`_consolidation_running()`): probe the flock, **shared** so that asking can never be something a real pass blocks on, and **`9<` never `9>`**, because `>` truncates the holder's file at open. Probe whether flock works *here* before reading a refusal as contention — BusyBox answers an unsupported flag with the same exit status as "the lock is held", which is the bug that once stopped memory updating at all. What is left is a warning worth acting on: an flock dies with its process, so a lock still held past any plausible pass is a live process genuinely stuck. The honest version of the question the old check was asking belongs to the queue, not the file — facts queued past 26h with nothing filing them, the same threshold `_consolidation_stale_hours` uses. And the test that was supposed to hold this asserted the *script* rather than driving it, so `tests/test_memory_learning.py` lifts `consolidator_lock_check` out of the real file, runs the old recipe on the same fixture to show it warning, and holds a real flock from a subprocess for the cases that must still warn.
- **A consolidation pass rewrites a whole document, and is budgeted like one.** It is a single turn producing memory.md *plus* voice.md — up to 10 KB — so its Claude timeout is 480s, the same as an insight run. At 120s it was a coin flip on a full document, and every loss reported itself as `Claude invocation failed (not authenticated?)` because stderr went to `/dev/null` and the exit code was never read: the queue never moved, the button never worked, and the log sent people to redo a working sign-in. **Never swallow stderr on a pass that can fail for more than one reason** — 124 is `timeout`'s and says so by name; anything else carries the CLI's own last line. **And stderr is not where the CLI says why**: in `-p` text mode its own verdict on a failed run — `Error: Reached max turns (1)`, `Execution error`, an API error, a signed-out account — is printed to STDOUT with exit 1 and nothing on stderr (read off the 2.1.295 bundle: the text printer writes through the stdout writer). The pass read stdout as the answer and deleted it on failure, so a house's journal held six `crash` rows in a day reading `claude exited 1` with the reason thrown away. It also loads no tools (`--tools ""`, the deny kept beside it): `--disallowedTools "*"` alone leaves every tool in the model's list, so a model reaching for Write spends its one `--max-turns 1` turn and the CLI ends `error_max_turns`; a CLI that rejects `--tools` loses that flag and only that one, and a retry claims a fresh session id rather than resending the spent one (`TestTheConsolidatorLoadsNoTools`). It asks for `--output-format json` now: the envelope goes to `brain_journal_record --envelope` as the authority, the answer is its `result`, an `is_error` on an exit 0 is still a failure, and the log line carries the envelope's words, then stderr, then stdout's last line. `record_shell` takes an envelope with no `result` (an `error_max_turns` one) by its `errors` and then its subtype, never `claude exited 1`. `TestTheConsolidatorHearsTheCliItRuns` uses a stand-in that answers the way the CLI does, where the older fixture wrote its error to stderr — the shape the code guessed. `/api/memory/consolidate` **starts** a pass and does not await it (`_consolidate_task`), because a request cannot outlive a minutes-long pass; the outcome is read back from `/api/memory/state`, which is a flag, not the 19 KB knowledge payload the tab used to poll every 2.5s.
- **A study session runs with the analyst's tool lists, refuses if it cannot read them, and wave 1 of this file claimed both before either was true** (`scripts/brain-learn.sh`). What was written down was "study sessions run read-only"; what shipped passed **no tool flags at all**, so it inherited `/config/.claude/settings.local.json` — Bash, Write, Edit and the whole MCP surface — on a path an automation can reach through the `brain.study` service. The lists are read out of `engine.py` at run time (`ANALYST_TOOLS`, `ANALYST_DENIED`) rather than copied into the script, because two answers to "what may an unattended run touch" is exactly how an acting tool reaches one of them; and when they cannot be read the run is **refused**, not made unrestricted, since a study that cannot be scoped is not a study that should run with Bash. Nothing about what it *writes* changed: the facts and findings are filed afterwards by the script, out of the JSON the session returned. The study watcher also passes the request's own `max_turns` through, so onboarding's lighter syllabus is a setting that does something rather than a field nobody read.
- **The deep check's memory probe was the most droppable line anybody could hand the consolidator** (`doctor.MEMORY_FACT_PREFIX`). It read `brAIn deep check marker <epoch> — ignore this line.` and the pass it is handed to is a Claude turn told to merge what it is given into four sections of facts about the HOUSE, to dedupe, and to exclude one-off commands. A working pass is right to drop that, and the stage then reported *"a pass consumed it without writing it down"* — the sentence for a broken memory pipeline — on installs whose memory was working perfectly. The probe is shaped like what it is measuring now: a plain durable fact about a device, in the form the document is full of, still saying what it is so a leftover can be traced, and still removed by the cleanup that fails if it cannot. **That rewrite kept the clause that made it droppable and the verdict it had earned** — see the `stage_memory` bullet below, where the probe stops describing its own subject as about to be deleted and the case becomes a skip rather than a failure, because a pass that filed nothing and a pass that judged this one line not worth keeping are genuinely two things and only one of them is a fault. The related hole is real and is NOT closed here: **the drain is per pass and the filing decision is per fact, and nothing reconciles them** — deciding which of twenty queued lines should have survived is the model's judgement and re-deriving it would be a second consolidator — so what the pass does instead is stop the case being silent, logging when it consumed lines and left the document unchanged, and counting the corrections among them separately because those are the ones somebody typed by hand and is waiting to see the effect of.
- **Hypotheses replace open-ended questions**: capped at 3 open, 14-day expiry, answered ones become plain memory lines and the record is settled. Rejected ones become a capped dead-ends block.
- **A queue's list and a queue's count are one read, or they are two answers to different questions.** The Memory tab's "waiting to be filed" counted the memory inbox — every fact any writer has queued — while LISTING the facts ledger minus anything whose `ts` predated `.last_consolidated`. The ledger only holds what the *analyst* discovered, so corrections, confirmed guesses, facts taught from the panel, voice, study sessions and anything another add-on left in `/share` were counted and never shown: nine things waiting above four cards, and neither number wrong. `_inbox_items` serves the actual lines now and `h_knowledge` reads both in one call. A line's id is a content hash (`_inbox_id`), because nothing stamps one and `ts` is not unique — one insight run queues three facts in the same second — and two lines that say the same thing from the same source *are* the same fact. The rendered list is capped and the count is not, so an over-long queue says what it is not showing rather than disagreeing again more quietly. **✕ drops the line and asks the consolidator for nothing**: a queued fact has by definition never been filed (the consolidator archives what it consumes), so the old `FORGET:` request was asking to strike a line the document mostly did not hold. `FORGET:` itself is unchanged — `brain memory forget` still writes one.
- **Knowledge is browsed by what a fact is about** (`facts_store.browse(subject_areas=)` → `facets.subjects`, `paintFactSubjects`). **One room is one row however many ids it was filed under** (`facts_store._fold_rooms` / `_room_key`): a run files under the area id it guessed, so the rail read "Laundry, laundry room" and "Irrigation, Irrigation"; area facets that name the same room (case-folded, a trailing "room" dropped) fold into one whose id is every id joined by `|`, which `browse` reads back as any-of. Every room and device brAIn has a fact about, with how many, devices grouped under the room `_NAMES` says they are in — a sticky rail beside the list on a wide screen, an optgrouped select at ≤899px — counted under the search, kind and source in force but never the subject filter itself, so picking one never shrinks the list of others. The subject chip on each fact narrows to that subject, the kind pills carry counts (All · Rooms · Devices · House · Rules you set), *Taught by* and the sort are selects again, the filters in force are removable tags (`#kActive`), and Delete is a bin on the row rather than a ⋯.
- **A guess is filed with the day it means** (`hypotheses.absolute_days`, `cases._from_hypothesis`'s `asked_at`). "Yesterday afternoon" read a week later is a different afternoon, so `propose` writes today / yesterday / this morning / last night / tonight / this afternoon or evening as the weekday they meant, and the question card says "Asked N ago".
- **Dismiss on a question is a snooze the hypothesis store understands** (`hypotheses.snooze` / `_asked_at`).
  - The guess stays `open`, leaves every screen, and does not hold one of the `MAX_OPEN` slots while it sleeps, so brAIn can ask something else meanwhile.
  - Its TTL runs from `max(ts, snoozed_until)`, so a guess dismissed on day 13 is not expired the morning it comes back.
  - The two shell retirers (`brain-memory.sh`, `brain-memory-consolidate.sh`) and `brain-learn.sh`'s slot count read the same rule. Three writers of one queue disagreeing about which guesses are live is the drift.
  - `/api/findings` no longer hands a sleeping guess back as a loose card.
- **The weather is arithmetic, a calendar is somebody else's text, and an occasion is a fact that expires** (`panel/occasions.py`).
  - **The read.** It is nightly-ish (`INTERVAL_S` 12 h), over `_ws_calls` with `return_response` (`weather.get_forecasts` daily and hourly, `calendar.get_events` for the opted-in ids only). A refusal is named, never read as a quiet week.
  - **Weather needs no model.** Frost, heat, heavy rain and gale come from `notable_weather` over the forecast's own numbers, with Fahrenheit converted. A model rewriting "−3 °C" can only get it wrong.
  - **Calendars.**
    - They are opted in through `settings_store.occasion_calendars`: default none, `clean_calendars` refuses anything not shaped like `calendar.x`, and an unreadable value falls back to none.
    - Every title and description goes through `untrusted` (instruction-shaped lines, role markers, fences, tool-call shapes, unlock/turn-off lines and URLs stripped) and is fenced as numbered data.
    - The Haiku turn must cite `event:<n>`. Its numbers must be in that event, its kind is a closed set that excludes weather, its dates are clamped to the event and the window, and health words are dropped.
  - **Filing.** Occasions are filed through `facts_store.add(source="occasion", predicate="occasion", expires=…)`. This is the first writer of `expires`, which `retrieval_block` already honoured.
  - **A closed gate.** It keeps the calendar occasions an earlier read found rather than blanking them. "I could not ask" is not "nothing is coming".
  - **Never acts.** This module has no route to a service call or a proposal.
- **A facts store under the document, and the document stays the one thing you edit** (`panel/facts_store.py`). `memory.md` is prose and carries no provenance: nothing in it says who taught a line, when, or from which run, and every run was handed the whole 30 KB whether it was about the kitchen or the boiler. The store is a **reader of the inbox and never a drain** — `ingest_inbox` files every line that passes through as one fact tagged with its subjects (`tag_subjects` over the registry the last checks pass saw, `_FACTS_CTX`; entity ids, `area:`, `person:`, `house`), its source, its `observed` date and its `run_id`, keyed by a content hash so the same fact from two writers is one row; the consolidator still archives the inbox and still has `memory.md` to itself. `retrieval_block` is what runs get now: the core facts (a share, `MEMORY_HEAD` first) plus the facts about the entities, areas and domains the run is reading, under `RETRIEVAL_CHARS` — `server._memory_block` at the brief, the weekly, the first look, both investigate sites and curiosity, `ha_data._memory_for` for the bundle, with the whole document as the floor when the store is empty. Capped at `MAX_FACTS` and `PER_SUBJECT_CAP`, oldest and lowest-confidence first. `/api/facts` lists and `POST /api/fact/{id}/forget` drops — the id is a hex hash, checked before it is used — and the Knowledge tab renders them with the subject chip, the source, the date and **See the run** through `viewConversation` over the same `run_sources` lookup the Chats rail uses, so "why do you think that" opens the conversation that said it. Forgetting a fact touches the document not at all: a line already filed there is edited there. **And the store never creates its own directory** (`facts_store.writable`): run.sh makes `/config/.brain/memory` before the panel starts, so a missing parent is a dev checkout or a test — `publish_state`'s rule — and the first full-suite run found exactly that, a dozen fixtures patching `MEMORY_INBOX_DIR` to a temp directory while the scheduler's ingest wrote their queues into the real `/config`, where `test_memory_prompt_budget` then read them back as the retrieval block instead of the whole document it was asserting on. **House › What it knows is the teach box and this list and nothing else**: chips are Rooms · Devices · House with no counts, the source and **See the run** sit in a row's detail behind a press, and forgetting is **⋯ › Delete** after a confirm. The brief, the measurements, the memory document and its queue left the pane (their loaders stay in `app.js`, guarded on their markup); the document and its queue came back as a fold when ⚙ › Memory was retired (*What each run is handed*, below, and panel.md).
- **The document is the curated truth, and the store answers to it** (`facts_store.reconcile` / `server._reconcile_facts`). `facts_store` ingested every inbox line it saw and nothing a person did to memory reached it: `brain memory forget`, an edit to `memory.md`, a clear, the inbox ✕ and every Undo changed the document or the queue and left the fact being handed to triage, the Resident, the brief, the weekly report and every card — the store most panel runs read since 2.2, curated by nobody. `reconcile` runs on the scheduler's minute and puts every row in one of three states read off the two things a person can see: **pending** (its line is still in the inbox, so the consolidator has not judged it yet), **kept** (the document reflects it: `REFLECT_SHARE` of its claim tokens in one line), **dropped** (neither, and only after a pass ran — a fact the consolidator chose not to file is a fact a person never saw). A kept row that leaves the document is forgotten, because that is somebody deleting a line; an emptied document forgets everything not pending, because that is a clear. `KEEP_SOURCES` (corrections, facts a person typed) and every `exception:` row survive all of it: the document is a summary, and a summary not quoting a correction is not the person withdrawing it. The pass is skipped when its input digest has not moved, and the digest is **re-taken after its own write** — the first cut took it before, so the pass's own write moved it and every tick ran the pass again. `FORGET:` lines in the inbox reach the store through `forget_matching` (token share, `FORGET_SHARE`), the inbox ✕ and Undo through `forget_text`, and `_queue_memory_fact` carries a subject and the run's own session id so a forgotten line can be traced to the one row it made.
- **Memory is reviewed on a press, and a removal is a proposal like any other** (`panel/memory_cleanup.py`, `/api/memory/cleanup*`, Knowledge › **Clean up**). Memory only grows: nothing read the whole document and the facts store and asked whether a line still deserves its place, so a replaced device, a wrong guess, a one-off evening and brAIn's own bookkeeping were handed to every run as true. One `run_analyst` pass (job `memory_cleanup`, a PRESS seat, a maintainer job so it is started and never awaited) reads the numbered document lines (`doc:N`, headings excluded) and the stored facts (`fact:<id>`) with Home Assistant's reading tools — so "wrong" is checked against the registry, not guessed — and proposes removals with a reason from a closed set (`wrong`, `useless`, `error`, `duplicate`, `stale`) and a sentence. `parse` drops an id nobody offered, a reason outside the set, an empty why and the same line twice. **What a person said is never offered**: `correction`/`person` sources and `exception:`/`judgement:` predicates stay out of the digest, `facts_store.KEEP_SOURCES`' reason. **The document keeps one writer**: Apply removes facts with `forget_ids` and turns each document line into a `FORGET:` line in the memory inbox (source `cleanup`) and starts a consolidation pass, so the consolidator strikes it exactly as it does for `brain memory forget`; unticked rows stay on the list, Discard clears it. `tests/test_memory_cleanup.py` drives the runner and the routes with only `run_analyst` and `_consolidate_now` stubbed and asserts memory.md was not written by the route.
- **A fact is filed as a claim about a thing, in whole words, once, and a fact about brAIn's own bugs dies with its release** (`facts_store.clean_subjects` / `resolve_area` / `clean_text` / `_folds` / `about_brain` / `outlived` / `_repair`, `memory_cleanup.OUTLIVED_WHY`).
- **A machine's reading of one moment lives two days** (`facts_store.is_moment` / `MOMENT_DAYS` / `REPAIR_VERSION` 2). "Moved across 69–72 °F in the last 12 hours" and "frozen right now" were handed to every later run as standing facts. A fact naming a recent window or the present (`_MOMENT_RE`, with `_DURABLE_RE`'s habits excepted) from a machine source gets `expires` two days after it was said, through the ordinary `_expired`; never `KEEP_SOURCES`, never a row with a predicate. The repair gives a stored one the same life from its `ts`, so last month's ages out on the first pass.
  - **Subjects are things.** `ha_data.ENTITY_ID_RE` allows a digit-only domain, so a decimal ("69.98") and a file name ("automations.yaml") were filed as device chips. `entity_shaped` wants a letters-only domain of two characters or more and an object id that is neither all digits nor a file suffix; where the last checks pass's registry is known (`_FACTS_CTX`, handed in as `registry`) an entity must also be in it. `person:`, `check:` and `house` stay, anything else is dropped, and a fact left about nothing is about the house. The tagger's scan applies the same shape rule when it has no registry.
  - **One room is one area id at filing**, not only on the rail (`_fold_rooms` stays as the display-side net). `resolve_area` takes the exact id, then the area's name, the id read as words, then its aliases, compared by `_room_word` (`_room_key`'s fold, one function now), and drops a room no area is called while the area registry was readable. With no registry the subject is kept as written, because "could not ask" is not "no such room".
  - **Text ends on a word and names what it means** (`settle_text`, `name_registry_ids`). Over `MAX_TEXT` is `textclip.clip`; a text exactly at the cap ending on a letter was some writer's slice and is cut back to a word with "…". A 32-hex device or config-entry id becomes the device's name or the entry's title, or its first eight characters and "…"; an entity's own hex object id is left alone. `KEEP_SOURCES` text is only ever cut at a boundary. A row whose text was cleaned or folded keeps `said` (hashes of the queued lines it came from), so the reconcile's *pending* and the inbox's ✕ still recognise it.
  - **A paraphrase or a newer reading of the same state replaces the older row** (`_folds`, at ingest through `near_dedupe`, and over the stored rows by `_repair`). Newest wording wins, `first_seen` is the earliest, and `folded` carries a short provenance list. A recovery ("live again", `_RECOVERED_RE`) supersedes older readings about a subset of its entities; a new fault supersedes only an older recovery, because a low battery and unavailable can both be true. Never a `KEEP_SOURCES` row, a row with any predicate (an exception, a judgement, an occasion) or an `occasion` source; a person's sentence absorbs its paraphrase rather than being replaced. Clean up stays the place for judgement calls.
  - **Every row carries the `version` it was filed under** (`ADDON_VERSION`, read at call time). `about_brain` is true only when the text says something is broken (`_BROKEN_RE`) AND the fact is about brAIn: a subject among the `brain` integration's own entities (`self_entities`, off the registry's `platform`), or text naming brAIn, "the add-on", MCP or a snake_case tool. Either half alone is a house fact ("the ESPHome add-on fails to compile", "brAIn reads the hall sensor"). Such a row is `_expired` once a newer parseable version runs, corrections included, and never a rule; `dev` expires nothing. `memory_cleanup.digest` offers an outlived row even when a person wrote it, with the two version numbers as its `stale` reason, and `parse` puts it on the table whether or not the model named it.
  - **The store is repaired once per rule set and per amount of context** (`REPAIR_VERSION`, `_repair_mark` in the reconcile state, checked ahead of the digest's early return), so the registry arriving after boot repairs again. The repair keeps a well-shaped entity the registry no longer lists (the orphan rule ages it out) and stamps an unversioned brAIn-bug row with the running version, so it expires at the next upgrade. `tests/test_facts_filing.py` drives each rule through the real inbox sweep and the real reconcile.
- **Curiosity asks for room before it spends, and a refused guess is deferred rather than settled** (`curiosity.status_for` / `deferred` / `server._repropose_deferred`). `_ask_why` spent a Sonnet run, got a guess, found the hypothesis queue full (`MAX_OPEN`), dropped it, and settled the subject for good: money spent, question never asked, subject closed. The budget is now asked before the run, and a guess the queue refuses (`REFUSED`) is stored `deferred` with its answer, re-proposed for free when a slot frees — the run already happened, so re-running it would buy the same answer twice.
- **The terminal and the chat teach memory, off Claude Code's own `Stop` hook** (`scripts/brain-memory-extract.py`, wired in `run.sh`'s settings beside the `PreToolUse` snapshot). Voice files facts with `remember_fact` during the turn; the two faces the most knowledgeable person in the house types into taught nothing. Four rules. **The hook is never felt**: it parses stdin, decides in one bounded ledger read, hands the work to a detached child and exits 0 — the extraction (a transcript tail, one cheap run on the memory tier, an inbox write) happens after the CLI has moved on, `test_it_exits_at_once` measuring the wait. **Only unclaimed conversations** — `run_sources` is the contract, so an id nobody claimed is one a person typed, and voice, study, the consolidator, doctor, the automation listener and the Resident are all skipped by having claimed theirs. **`worth_extracting` judges the PERSON's words alone** (`said`, never the assistant's reply), because the first cut matched "remember" in the model's canned answer and spent a run on every turn. **Every writer goes through the inbox**, a `kind: correction` lands under `source: correction`, and `learning: false` switches it off through `BRAIN_ASSIST_LEARNING` — read from the environment the terminal's shell sourced, or off `/data/.brain_env` itself for the chat's process, which never sourced it.
- **A guess answered in Home Assistant is a request, not a write** (`requests.write_hypothesis_request`, `finding_requests.HYPOTHESIS_KIND`, `server._apply_hypothesis_request`). `brain.answer_question` appended to a file nothing read and queued the typed answer as a high-confidence fact, so a "no" became knowledge and the guess stayed open. It now rides the finding-request queue (the order between kinds matters) and the panel closes the guess through `_answer_hypothesis`, the Findings tab's own Yes/No. The integration refuses what could never be applied — an answer that does not open with yes or no, a guess that is not open, two guesses matching — and the open guesses' ids ride on the *Questions waiting* sensor (renamed from *Waiting on you*, unique id kept) so an automation can name one. There is no `brain.case` service; the docs said there was.
- **The memory extractor reads what is new, from somewhere that costs nothing** (`brain-memory-extract.py`). It runs from `CLAUDE_HOME` with its own `--system-prompt`, `--tools ""`, `--strict-mcp-config`, `--setting-sources ""` and the engine's isolation settings. Those settings are written out in the script and held equal to `engine.isolation_settings()` by a test, because the hook must start without the panel. Each conversation remembers the uuid of the last message a pass read. The next window is what came after it, with the previous exchange as EARLIER context to extract nothing from. One new message has to carry teaching language. A message judged not worth a pass still moves the marker, and one held back by the spacing is read by the next pass.
- **Why somebody did something is the one fact a house never records, and it is the fact worth having** (`panel/manual_ledger.py` + `panel/curiosity.py`). `actions.py` can say a person turned the sprinklers on at 19:04. `routines.py` can say they do it most evenings at about seven. Neither can say **why**, and an automation built on the *when* alone fires at seven for ever and is wrong the first week it rains — the reason is the lawn being in full sun until six, or water being metered cheaply after seven, and neither of those is in any state, statistic or logbook. So this is the one producer whose output is an **explanation** rather than a finding, a proposal or a measurement: it reads a manual action brAIn cannot account for, spends one Claude run looking at what else was true at the time, and files a durable fact or a question. **The selection IS the feature and it is deterministic.** A house produces tens of manual actions a day and a run costs real money, so most of `curiosity.py` is the decision *not* to ask — and nothing asks a model which events are interesting, because that is a model call per event to decide whether to make a model call per event. `worth_asking` is arithmetic over a ledger, taken before anything is spawned, and an empty answer costs nothing; `brief.worth_saying`'s rule with more riding on it, since a brief nobody needed is a wasted turn where a question nobody needed is a wasted turn **and** a line of somebody's attention. The budget is `MAX_PER_DAY` 1 and `MAX_PER_WEEK` 3, and they are numbers rather than options for the reason the turn caps are gone: the two settings on offer are low enough to make the feature pointless and high enough that nobody should have been asked. **A question is asked once about a subject, and the subject is settled BEFORE the run** — `_brief_loop`'s stamp, for a sharper reason: a run that crashes having spent the money must not leave the identical question to be asked again every six hours for ever. **But a guard that refuses has to change the next attempt**, so an `unknown` is re-askable, and what re-opens it is **more evidence, never the clock** (`RETRY_EVENTS` further occurrences) — a retry on a timer buys the identical answer over the identical data on somebody else's money. **A confidence that comes without the thing that makes it actionable is demoted, not believed**: an `explained` with no `fact` would file nothing anywhere, so calling it explained settles the subject for ever having learned nothing, which is the one outcome worse than not asking. **The three answers go to three places that already exist** — a fact to the memory inbox (never `memory.md`, which has one writer), a guess to the **hypothesis queue**, which is exactly what that queue is for and costs no new store, no new tab and no new badge, and an `unknown` to nowhere, because *"brAIn could not work out why"* is a fact about brAIn rather than about a home. The loop then closes through machinery that was already there: a confirmed hypothesis becomes a memory line, a rejection with a note becomes a correction, and memory is injected into every future prompt. **And it answers to the three gates every scheduled Claude run answers to** (`_offer_milestones`' rule — a credential, `auto_enabled`, the usage budget), where the *pressed* route skips the budget on purpose, because "automatic insights pause; asking by hand always runs" is one promise with two halves. Nothing is settled by a pass a gate stopped, so a paused house asks on the pass after it is unpaused rather than having silently spent its questions while paused.
- **Some questions a house should not ask, and that is a refusal rather than a ranking** (`manual_ledger.EXCLUDED`). Locks, alarm panels and the domains that track where people are: *"why did you unlock the front door at 02:40"* is a question with a correct answer and no good reason to be asked by a piece of software, and one badly-judged question of that shape costs more trust than every well-judged one earns. A ranking is a thing that gets tuned; this is not in the ranking. The other half of the same judgement is in the prompt, because a domain refusal cannot stop a *run* reasoning its way to "somebody was unwell" — the contract forbids saying anything about health, whereabouts, who was home, sleep or household, and says there is no exception to it, so a reason that is about a person rather than about the house comes back `unknown`. **Voice counts and `routines.py` is right to exclude it**: that module builds a **time trigger**, and one built on somebody having asked Assist is built on a sentence rather than on a time, where this is about to ask a **question** — and a voice command is the most informative manual action a house records, because the person said what they wanted in words. `unattributed` is excluded from both: a wall switch and a device's own integration reach Core identically, and a question about a press nobody can prove happened is one brAIn invented. The domain **order** is the ranking, made where being wrong is cheap (`chore.waiting`'s trade): a script or a valve carries a reason worth keeping and a lamp mostly does not, so lights are eligible and never outrank a pump. **The floors are looser than `routines.py`'s on purpose** — that module is about to build a trigger, which is wrong if it fires at the wrong end of an hour, where a question is answerable about "most evenings" as well as about 18:40. **And the odd press is the half no measurement could see**: a subject *already* having a shape is what makes "outside it" mean anything, or the first press on a newly installed device is the strangest event in the house every time; the distance is `rhythm.circular_distance` (lifted out of `circular_spread` so one implementation answers it), because 00:10 against a usual 23:50 is twenty minutes and a straight subtraction makes every late evening the oddest press ever recorded; and the press is excluded from the shape it is judged against, or it drags the centre toward itself and the oddest thing in the house comes out ordinary.
- **A drained queue is the proof the memory pipeline ran, and the stage read its silence as a fault** (`doctor.stage_memory`). The probe read "… is a diagnostic entity brAIn creates while checking itself; **it is removed again straight away**", and the consolidator's own prompt says "NEVER include secrets, credentials, transient device states, or one-off commands" — a line whose second half states that its subject is about to be deleted is a transient device state written out longhand, so the pass that dropped it was the pass working. The stage answered *"a pass consumed it without writing it down"*, which is the sentence for a broken memory pipeline, on installs whose memory was fine. 1.49.0's rewrite took out the "ignore this line" and kept the clause that made it droppable, along with a bare epoch mid-prose and a subject — the fixer helper — the deep check was never actually creating. What settles the verdict is the consolidator's own ordering: it archives the inbox **only after** `memory.md` is written, and every failure above that returns with the queue standing, so a queue that emptied proves the pass read the facts, rewrote the document and filed the inbox away. The only thing left unproven is whether this one line was worth keeping, which is the model's judgement and which the consolidator's log already calls "a judgement, not a failure" — so it is a **skip** naming the case, `clear_resolved`'s rule wherever "I could not tell" and "it is broken" are different claims. A queue that did not move is still a failure, and now drops the probe back out with it: the marker is still in the inbox on that path, and the next ordinary pass would file this check's own probe into somebody's `memory.md` with nothing left to remove it — the harm the stage's docstring promises not to do, arriving by the one ending that had not been given the line that prevents it.

The owner: *"It's not clear to me what is imported on each new conversation vs what's in knowledge."* The answer was spread over six builders and no screen. The route lists six kinds of run — a conversation in Ask, an insight card, a voice request, a first look, an investigation, the overnight check — each with what it is **given at the start**, what it is given **with each message**, and what it may **look up**, every part a byte count (and a ~4-chars-a-token estimate) measured now from the real text (`CHAT_IDENTITY` + the mode lines, `_personality_lines`, `_chat_house_lines`, `/config/CLAUDE.md` and the memory excerpt and your notes inside it, `ANALYST_SYSTEM`/`SYSTEM_PROMPT`, `knowledge_store`/`findings_store`/`hypotheses.prompt_block`, `resident`/`sre` rules, voice's `brain_voice_context.system_prompt`), or the cap its builder holds to, marked `upto` (`CHAT_CONTEXT_CHARS`, `RETRIEVAL_CHARS` + the document's head, `HOUSE_CHARS`). Lookups are `engine.ANALYST_TOOLS` for a card and an investigation and every tool the MCP server lists (read off its source) for a conversation, grouped by name into plain words — a read-only tool with no group fails the test. **What the code does, said plainly**: a conversation carries the document only as the excerpt in CLAUDE.md (8 KB by default, written at start and after each filing); the facts store is pushed per message only on the **chat** face (`brain-chat-context.py`, wired in the chat's own `--settings`) — the terminal face, the default, gets none and the page says so on a terminal house; a card, a first look, an investigation, the brief and the weekly get `retrieval_block` instead of the document (the document capped when no facts exist); voice gets `voice.md` or the document's first 2 KB and never CLAUDE.md; the overnight check gets no memory and no tools; every run with tools can search the store with `recall`. **No text leaves the route**, only names, sizes and where a part is changed — the test plants a token-shaped string and the document's lines and asserts neither appears.
