# BRight specifics

Ports, playback checks, analysis, effects, the choreographer, show editor, parties, director jobs.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

What each rule cost to learn is in `docs/notes/history/bright.md`. Tests named here were removed in November 2026 with the old suite; the rules they held still hold. The `measure-*` scripts are the hand tools in `tests/manual/`, not gates.

## The port and the panel

- **A host-network add-on does not get to choose its port.** `host_network: true` is required (LIFX discovery is a UDP broadcast and the replies come back to the sender's own address, which a bridged container never sees), and it makes the panel's port a **real port on the host**. **A guard that refuses has to change the next attempt, and a number in a manifest cannot change anything.** So `ingress_port: 0`, which is what Home Assistant documents for exactly this: the Supervisor assigns a free host port and the add-on reads it back from `/addons/self/info`. `panel/panel_port.py` is the one place that lookup lives (env → Supervisor → `DEFAULT_PORT`, and `DEFAULT_PORT` is a fallback for a machine that cannot be asked, never a claim that a port is free); `run.sh` resolves it once, exports it, and writes it into `/data/.bright_env`, because the panel, the HA bridge and the log line have to be talking about the same port — a bridge posting to a port the panel is not on is every show service timing out. BRUH Minecraft still pins 8099 and has the same latent collision; it has not been hit, and changing a working add-on's port is not a fix for one that is broken.
- **The port is bound before anything claims it is listening.** `panel_port.bind` takes the socket first and `web.run_app(..., sock=sock)` serves on it; a busy port ends in one sentence naming the port instead of an aiohttp traceback, after a short retry whose only real case is a previous panel that has not finished dying.
- **A dynamic port costs the `watchdog:` URL, so the watch moved inside.** The Supervisor's placeholder needs a port number written into `config.yaml`, and a watchdog pinned to a fixed port would poll whatever stranger holds it and restart BRight on its behalf. `run.sh` polls `/api/health` on loopback instead — four consecutive misses, thirty seconds apart, then it kills the panel so the container exits and the Supervisor's restart-on-stop brings it back. Every add-on is watched by *something*, and no add-on that gave its port away names one in a watchdog URL.
- **Nothing on the BRight panel is public.** The health poll runs inside the container over loopback, which `_lan_gate` already trusts, so no prefix needs an exemption. Everything else about the gate is Minecraft's, for Minecraft's reason — the peer address, never `X-Forwarded-For`.

## Playback and the library

- **A service call that was accepted is not a speaker making a sound, and every layer of this add-on used to report the first as the second.** `media_player.play_media` returns when Core has *taken* the command; Core then resolves the media, signs a path, puts a host in front of it (`get_url`) and hands the URL to a speaker that fetches it afterwards, on its own, over the network. Nothing about that is visible from the call. So `playback_check.check` walks the links — file, media id, host, player, command, playing — and stops at the first that breaks, because telling somebody their speaker never started is noise when the file was never there. **The host step is the one that took research rather than reading**: Chromecast, Google and Nest speakers resolve names through Google's public DNS (8.8.8.8) rather than the router's, so an `internal_url` of `http://homeassistant.local:8123` is a name the speaker is told does not exist; nothing plays and nothing errors. An *unset* internal URL is the good case (Core falls back to the machine's own IP). `wait_for_playing` is the step that separates the two claims, and the conductor runs it in the background after every show starts, because the cue list cannot wait — the clock was anchored at the play command — but a room that stays dark while the panel says "Running" is the same failure with the lights on.
- **Media sources are WebSocket-only, which is why `panel/ha_ws.py` exists.** `media_source/resolve_media` is the same call the cast integration makes before it hands a URL to a speaker, so asking it is the closest thing to trying it — and it is the only way to catch the one guess BRight cannot make safely: `local` is the *default* id of Core's local media source, and an install that sets `media_dirs` replaces that default, which turns every media id BRight builds into Core's own HTTP 500. aiohttp's client speaks WebSocket, so this cost no new dependency; `ws_connect` takes no `timeout=` because aiohttp changed that parameter's type across versions and the image's aiohttp comes from Alpine. Test it against a real aiohttp server speaking Core's handshake, because a hand-rolled fake of a protocol proves only that the fake matches the code that mocked it.
- **Two sources of folders, one list, and neither is a second answer.** `music_folder` + `additional_music_folders` are configuration (they survive a reinstall, they are what an automation-minded person edits); `stores/folders.py` is what somebody ticked in the Library tab without editing YAML. `_music_folders()` merges them, ordered and deduped, and the scan dedupes by content hash so a folder nested inside another costs nothing. The *option* is read from `/data/options.json` rather than `/data/.bright_env`: a list cannot ride a shell string, because every separator is a character a path may legally contain (`/media/best of 80s:90s`). The picker browses the **filesystem**, not Core's media tree, because those have to be folders BRight can *read* — what Core will serve out of them is `/api/playback/check`'s question. Everything stays under `/media` because `media_content_id_for` builds a `media-source://…/local/…` URI, which Core only serves for files under its media folder: a folder outside it analyzes perfectly and never plays a note.
- **An answer that is dropped is a success nobody earned.** The integration's three services raise `HomeAssistantError` on a refusal, which is what puts a sentence in the automation trace (`bright.party_mode` with nothing analyzed must not give an automation a green tick and a dark room). The bridge reads the panel's own body on an error status, and `h_ha_entities` uses `states_or_error`, because `get_states` answers `[]` for an unreachable Core and for a home with no speakers, and "I could not ask" is not "you have none".

## Analysis

- **A version that nothing compares against is not a version, it is a comment.** `ANALYSIS_VERSION` lives in `library.py` (the module that owns the files, and the one whose `scan` has to read it), `is_stale` compares it, and `analyze_folders` re-runs anything older without being asked twice. Bump it whenever the analyzer gains a field a consumer reads. **`analyzed` stays true for a stale analysis** — it still has beats and a duration, the track still plays, and `server.py`'s party queue is built from exactly that flag, so downgrading it would silently drop every already-scanned track out of every party; `stale` is the separate, narrower claim. A missing `version` is *older*, never newer, or the very first analyses become the one set that can never be refreshed. Hits are `ANALYSIS_VERSION` 4 (the `band` field) and **5** (where the hits are actually found).
- **Rhythm says when a song hits; `analyzer/music.py` says what it is playing.** Sections and drops are a skeleton — a show built on them alone changes when the arrangement changes and sits still through everything in between, which is most of the record. Four extractors, one shared STFT (bigger frame than the beat tracker's: pitch needs frequency resolution where onsets need time resolution): **chords** (beat-synchronous chromagram against 24 triad templates, reported as *changes* only, because a show acts on the change and an ambiguous beat holds rather than flickering); **melody** (dominant pitch in the melodic register as note events — harmonic summing to prefer fundamentals over partials, **plus a sub-octave penalty**, without which the tracker follows the bass up into the melodic range the moment the tune rests and fills every silence with a phantom note); **phrases** (notes grouped into breaths, with the direction of the line, and the gap that ends one is measured in *beats* because half a second is nothing at 90bpm and two beats of silence at 160); **repeats** (beat-chroma self-similarity — coarse on purpose: it finds the chorus coming back, which is the repetition a show should answer). Every extractor has a floor below which it says nothing, because a confident answer where the audio holds none is the one failure that cannot be recovered downstream.
- **Accents are thresholded in the units of the thing being thresholded** (`detect_hits`, `_band_scales`, `KICK_TONE`). `band_flux` scales both bands by the **full-band** flux peak while `punch` sums only the two bands under 2kHz, about a hundred of a thousand bins, so punch is structurally a small fraction of 1 and an absolute bar never fires on a real mix. The threshold is a percentile spread of the track's own punch (`0.22 * (p97 − median)`, plus a floor at 15% of the loudest punch). **`band` had the same shape of bug one layer up**: under 250Hz is ~12 FFT bins and 250–2000Hz is ~93, so comparing raw sums answers "which band has more bins". `_band_scales` divides each band by its own p99 (a percentile, not the max: one enormous transient otherwise sets a whole band's scale) and `KICK_TONE` is **0.6**, not 0.5, because at 0.5 a bassless track's noise floor wins coin flips and hands the kick layer random snares. A ratio guard is the wrong shape: the low band is *always* the smaller of the two, so "low is much smaller than mid" is not evidence of anything. Grade it against synthetic mixes at ordinary levels, never against a stab louder than any real mix.

## Effects

- **An effect is the unit, and the map is what it travels through** (`panel/director/effects.py`). Twenty-two types (wash, fade, build, pulse, strobe, chase, sweep, breathe, sparkle, colour_cycle, rainbow, theater, stab, blackout, melody, harmony, colour_drift, saturate, level, hit, accent, aux), each a catalog entry plus one render function — the UI builds its whole form from `catalog_payload()`, so adding a type touches neither the panel nor the compiler. An effect names a `select` (ids, roles, zones, exclude) and **everything it does not name is untouched**, which is the whole reason a show is built from effects rather than scenes: most of the room is usually meant to stay still. `order` comes from the light map (`x`, `-x`, `y`, `-y`, `center_out`, `edges_in`, `snake`, `zone`, `listed`, `random`) and every ordering is total and deterministic — `random` is seeded by name, never `random.shuffle`, because a show somebody liked on Friday is the show they get on Saturday. Role manners are the default and an override: `respect_roles` caps brightness per role and keeps candles out of the harsh set, and an effect that means it can own a fixture outright says so. Parameters are **clamped, never rejected** — these files are typed by hand, and a show that refused to compile over `depth: 1.2` would be a worse tool than one that reads it as 1.
- **One rendering, two consumers.** Every effect renders to *actions* ("this fixture, at this moment, becomes this colour over this fade" / "runs this waveform for this many cycles"); `compiler.render_actions` turns actions into packets and `effects.simulate` turns the same actions into preview frames. A preview drawn from a second implementation of what an effect does is a preview of the second implementation — it would look right while the room stayed dark. The panel converts HSV to CSS and nothing else, because the frames ARE bulb colours. Every action carries the name of the effect that produced it and that name rides into the cue's `desc`: it is the only thread from a packet in a 2,000-cue timeline back to the line in the script a person wrote.
- **A LIFX waveform runs between the bulb's CURRENT colour and the packet's, which is why the beat pulse peaked on the off-beat.** A sine anchored on the beat is at the bulb's existing level *there* and brightest at half the period. `PEAK_PHASE` gives every shape the fraction of its cycle at which it is brightest and `peak_shift` is how far ahead of the moment a wave has to start; `_r_pulse` drops an anchor whose lead-in would land before t=0 rather than clamping it, because clamping moves the peak off the beat again quietly. The table must agree with `_wave_position`, because two answers to "where is this waveform brightest" is one too many and the simulator is what the preview draws. `_r_hit` deliberately does NOT shift: its wave travels *down*, so its brightest instant is where it starts.
- **A LIFX bulb runs exactly ONE waveform at a time**, which is how `halt_waveform` stops a show. So two of `BULB_ROUTINES` overlapping on one fixture is the later cancelling the earlier, and from a sofa that reads as an effect that mysteriously does nothing. `compiler._routine_clash` reports it on the effect's own row (naming what is being replaced) and the brief tells the director the rule; it is **reported, never refused**, because a stab interrupting a pulse on the drop is a real technique. The set must match what actually emits a wave action, so a new effect cannot join the class silently.
- **The brief's list of bulb-side effects is generated from `BULB_ROUTINES`** (`_routine_names`), because a hand-written copy drifts, and a model following a stale list exactly could write a show whose kick silently cancelled its snare. `schema_contract()` is the one place the contract is formatted; `_EFFECT_CONTRACT` takes the same `%(catalog)s` key and is a different template.
- **A swell is not a strike, and every rhythmic effect BRight had was a swell.** `pulse`/`breathe`/`sweep`/`colour_drift`/`saturate` travel smoothly up to a level and smoothly back; that is what "just a bunch of fading lights" describes. `hit` and `accent` are the other half: a `_set` to the peak with **no fade** (a fade still in flight would start the decay from somewhere between the two and lose exactly the attack) followed by a `saw` wave travelling to the floor. `saw` is not a parameter there — it is the only one of LIFX's five shapes that is monotone across a cycle, and the other four come back up inside it, which ducks rather than decays. Still one packet per light for eight beats, because the bulb runs the envelope. `accent` reads the analyzer's ranked hits rather than the grid (so it catches fills), scales the peak by `0.55 + 0.45 * strength` (an accent at 0.4 rendered at 0.4 is invisible beside a scene already at 0.55), and filters by `band` — `detect_hits` records which of the low and mid bands won each hit, which is the whole reason a kick and a snare can be on different lights.
- **Every effect BRight had was a brightness effect, because `SetWaveform` carries a whole colour and moves all of it.** `SetWaveformOptional` (message 119) is the same bulb-side engine with a per-channel mask, and it buys `colour_drift` (hue travels, brightness frozen) and `saturate`. `level` is the other half: brightness follows the analyzer's own 20Hz loudness envelope — the song's real shape. Its `gamma` is what makes it a lighting choice rather than a VU meter.
- **`melody` and `harmony` are the effects that consume it, and their silence has to say why.** Both render to nothing when the analysis carries no music — correct, and pixel-identical to a broken effect — so `effects.NEEDS_MUSIC` plus `Grid.has_music` let the compiler put the reason on that effect's own row in the editor (`entry["note"]`) rather than leaving a silent zero. `Grid` carries `notes`/`chords` alongside the beats: one context object, read off `analysis["music"]`, optional so a bench preview works through the same code. The Effects tab previews them against a **stand-in tune** (`_BENCH_SCALE`/`_BENCH_CHORDS` in `server.py`), because the bench is a synthetic track and an effect that previews blank there is indistinguishable from one that is broken. A note's **pitch class** picks its colour out of the *scene's palette*, never the raw hue wheel: a show whose colours are chosen by the tune and not by the scene is a show with no scenes. **`melody` places a note by its PITCH** within the track's own range (`Grid.note_range`, the whole track and never the window, or the same note lands somewhere different every section), so a run up the scale is a run of light across the room and a repeated note stays put — `follow: "step"` is the old march, kept because it is what somebody may want.
- **An effect whose selection matches no light is the one silence with nothing to do with the music.** It compiles, it saves, it plays, and the room stays exactly as it was. `script_actions` checks `resolve_fixtures` **first**, before the music/energy/hits reasons, because an empty cast explains the zero better than any of them. And `resolve_fixtures` matches roles and zones through `_key` (trimmed, case-folded) while ids stay exact: a zone is a name typed into the map and typed again from memory into a script, so "Inner Kitchen" and "inner kitchen" are one room.

## The script and the automatic show

- **The script language is version 2, and version 1 still compiles.** A scene carries `effects`; `moments` pin an effect to an instant. `motifs` and `features` are translated into their effect equivalents at compile time (`_from_motif`, `_from_feature`) rather than kept as a second rendering path — a vocabulary that grows must not invalidate what was written against it, and shows are artifacts people keep. `SECTION_LEVELS`, `ROLE_RULES` and the palettes are shared by both.
- **Automatic is the same file as hand-written.** The choreographer emits ordinary effect instances — there is no private vocabulary the automatic show can use and a person cannot, which is what makes "automatic but completely editable" true rather than aspirational. It reads the map for real: three or more moving lights get a chase (with a seeded travel order), two get `theater` alternation, because a chase across two bulbs is a flicker. A drop gets a `build` whose window **crosses the section boundary** — tension starts inside the section before the drop and ends on it — plus a `stab` and the aux switches.
- **The automatic show is four layers on different lights, not a texture per section** (`choreographer.LAYER_PLAN` / `LAYER_ROLES` / `plan_layers`). One look per section, run end to end, changes about eight times in a four-minute track and does nothing in between. Ground (harmony, seconds-long, the only layer allowed to feel like fading, on whatever is not carrying the beat: candles, strip), pulse (the beat, as a `hit`), hits (kick and snare, separately), voice (`melody` — **in the chorus** too, because it owns its own lights). **A fixture belongs to one layer and that is physics, not taste** — a bulb runs one waveform at a time — so `plan_layers` claims whole roles first (selecting by role is what survives somebody mapping a new bulb) and only **splits** a role by naming ids when a layer has nowhere else to go, which is what a designer does with six lamps and four ideas. `_entrances` puts a stab on a layer that has just arrived, and only where the energy *rises*: a layer arriving as a song thins out is the arrangement thinning out and wants no announcement. There is no fixed number of accents a song; a stab that owned every mover in the room was a budget, not a taste.

## Shows, versions and the show file

- **A track has many shows and one of them plays** (`library.list_versions` / `save_show` / `activate_version`). A compile never overwrites the show somebody spent an evening editing. The **pointer**, not a copy, is what makes it cheap: a compiled show is most of a megabyte on a busy track and this usually runs on a Pi, so `show_path` resolves through `versions.json` and every existing caller — the conductor, the party queue, the editor, the mirror — asks for "this track's show" exactly as before. Naming a version **pins** it, because the only reason to name something is to come back to it; the prune eats the oldest unnamed ones and never the live one, and an archive of nothing but named versions goes over the cap rather than refusing the save (a full archive that stops you working is the worse failure). Migration of a pre-versions track happens lazily on the first read and **moves** the files rather than copying them, so `os.replace` makes it atomic however the add-on dies in the middle.
- **The show file is the show, and it is openable** (`GET/PUT /api/show/{hash}/script`). Editing it goes through the same validator, compiler and per-bulb budget the director's own output does; a refusal names what to change (`raise an effect's step_beats, narrow its selection`) and leaves the show that was there untouched. Every compile mirrors the script to `/config/.bright/shows/<track>-<hash>.json`, because /data is invisible to Home Assistant and a file nobody can open is not editable. **The mirror is a copy and the copy is not the record** — editing it changes nothing until `POST .../script/import` reads it back, deliberately: a half-typed JSON file being picked up by a party at 11pm is not a feature. A broken one is reported with the JSON parser's own line number. The stale-name sweep before each mirror write is what stops a retitled track leaving two files for one show.

## The show editor

- **The show editor is a picture, and the picture is served by the compiler's own walk.** `compiler.script_actions` is the single route from a script to actions — `compile_show` renders those to packets, `director/preview.py` simulates the same list into frames. That is "one rendering, two consumers" at the scale of a show, and it is what makes a live editor honest: a preview that walked the script itself would be a preview of its own idea of it. Two shapes come out of it: `window` (frames at 15fps over a few seconds, for scrubbing) and `overview` (the whole song, one row per light, for the strip). `simulate`'s `start_s` skips emitting frames while still **applying** every action before them — sampling every fixture per frame is the expensive half and a window skips it; skipping the actions instead would preview a show that began wherever you scrolled to. **Every preview request carries the script being edited**, which is the whole of "live": the server previews what is in the editor, not what is on disk, and the compiler's refusals arrive next to the effect you just changed rather than at save. Nothing on that path writes.
- **The panel draws what the song is PLAYING, or the musical analysis is invisible** (`preview.music_lanes` + `paintLanes`). Three lanes on the waveform's own ruler: chords as labelled blocks (a name that does not fit is omitted, because half a chord symbol is a different chord), the melody as a contour against **the track's own pitch range** (a fixed MIDI axis flattens every song into the same middle stripe), and the drums with the kick low and the rest high. `preview.lanes` is the other half: one named row per effect, built from the **walk** rather than the script, which is what tells "this effect produced nothing" apart from "this effect is fine". What is listed under the editor is the **exceptions**: an effect that drives no lights, one whose analysis is too old, one whose waveform another cancels. When the show is fine that block is empty, never an inventory. The lanes are flat arrays (`[t, d, midi, s]`) because this is drawing data a thousand rows long. `measure-showeditor.mjs` fails on blank lanes, on four canvases that disagree about where 1:30 is, and on the exceptions block becoming an inventory.
- **A strip column is one instant across the room, never an average and never a per-light peak.** Averaging invents a colour the show does not contain. Per-fixture peaks **measured worse**: a strobe alternates bright and dark, and taking each light's brightest sample throws the dark half away. Effects layer and the last one to name a light at a moment wins, so an effect placed on the same instant as a stab that owns those lights changes nothing there, and the strip is right to show that.
- **An editor may not quietly rewrite what it opens.** The effect dialog edits ids, roles and rooms, carries `exclude` it has no control for, ships `DEFAULT_ORDER`/`DEFAULT_ALIGN` **from the catalog** rather than keeping a second copy of them, and omits a key it did not change. Ticking boxes must not turn a **role** selection ("every candle") into a list of ids, which is wrong the moment a candle is added. `measure-showeditor.mjs` asserts a no-op edit is byte-identical.
- **A row that misreads a selection is a row you edit by mistake.** `edDescribeSelect` renders what is actually there (roles, zones, ids), never a count of `select.ids` alone.

## Parties and stopping

- **The Party tab is one screen and the vibe is not on it.** A vibe steers the **director**, which is a compile-time decision, so it sits above the track list on the Shows tab, sent only on a **Claude** compile; in a party it could only ever reach a track with no show yet. What is left is one surface: tick the shows, press Play, ⏮/⏭ between them — and each row may **pin a version**, defaulting to the live one so the newest plays without anyone choosing it (`load_show(hash, version_id)`; a pin that has been pruned falls back rather than skipping the song). Saved parties are saved **sets** — a name on exactly what is on screen — and **Load** fills the screen rather than starting it, because seeing what Play would do is the whole reason there is only one surface. `party["tracks"]` and `bright.start_party` are unchanged, so automations keep working.
- **A Stop button that is always there is a button nobody trusts.** All three (Party, Shows, the Lab's sync proof) render only while `state.active` says a run is in progress — the conductor's own answer, written beside the status in `_write_state` so "idle" can never arrive still claiming to be running, rather than a string comparison against the words that happen to mean running today. `lights_busy` is the second, narrower question ("are cues still going out"), false once the cue list is spent and the lights are holding what the last cue left them at. One poller for the whole panel, because "is a show running" has one answer. The integration's sensor carries both, so a dashboard keys on the same flags the panel does.
- **Stopping puts the room back, and "back" is not always where it was.** Restoring the pre-show snapshot is right when the show interrupted an evening and wrong at 1am — what people want then is a scene they already have. A party (or a `bright.stop_show` call) may name one, and it is called *instead of* restoring, because two answers to "put the room back" would fight and the configured one wins. A scene that fails to run falls back to the snapshot, so the room never keeps the party colours. Parties are named saved evenings (`stores/parties.py`) — speaker, folder, vibe, allowed fixtures, end scene — matched case-insensitively, because the name is what an automation or a voice command types. `bright.start_party` requires the name so a typo fails loudly instead of quietly playing the default folder; `party_mode` merges a party's settings under anything given explicitly, which is what "the usual thing, but on the kitchen speaker" means. A party's fixture list is enforced at **dispatch** (`conductor.filter_cues`), not at compile: one compiled show serves every party, and a show cached per fixture-subset would be a cache keyed on something nobody can see.

## Director jobs

- **Asking Claude for something is a job, never a request** (`server._claude_job`). A show script takes minutes to write and ingress cuts a long request, so what reaches the browser is not the panel's error but the *absence* of a reply (`load failed`, `Failed to fetch`) about a director that is still working. All four Claude routes (compile, revise, describe an effect, invent effects) start a `jobs.py` job and hand back its id; the panel's `claudeJob` polls it and counts the seconds, because a spinner that never changes is a spinner people press twice. **That is the shape of the bug**: a latent limit becomes a failure months later, when the brief grows and the model gets slower, without a line of the code that breaks being touched. A second press returns the LIVE job's id rather than a collision, so both presses watch one run. Argument checking still happens before any job starts — a typo must not become a minute-long wait — and the director's timeouts (600s a script, 180s an effect) are the director's own budget rather than whatever a proxy will hold a connection open for.
- **`available()` answers one of six questions, and the folder outlives the listener that made it** (`panel/director_check.py`). `/config/.brain/tasks` is created by brAIn's automation listener at startup and left behind when that listener stops, so the folder existing says nothing about brAIn running. The listener **claims** a task by renaming it before doing any work, so an un-renamed file after `CLAIM_GRACE_S` (30s, six of its 5s fallback poll cycles) is proof rather than a guess, and it is a *different sentence* from a task that was claimed and never answered — one names the switch to turn on, the other points at brAIn's log. `director_check.check()` walks the whole chain (brAIn → task folder → BRight can write there → something claims → something answers → the room has lights) and stops at the first break, the shape `playback_check` uses for audio; it runs a real trivial round trip rather than describing one.

## The Light Map

- **A dot has to say which light it is.** Names ride on the map (a hover tooltip does not exist on a phone); a tap selects, and the dot, its row and a bar above the floor all agree on which light that is, with the role picker and Remove on the selection. Three geometry details are load-bearing: a press that never travels is a tap (so tapping a light cannot nudge it), a 44px dot hangs half outside its own coordinate (so `placeDot` clamps the *drawing* inward, never the stored position, or a light at x=0 is half off a floor that clips), and the label flips inward at the edges. Set the 44px touch floor once, not inside `.demo-controls`, or a control added later renders at the browser's default **19px**. `tests/manual/measure-lightmap.mjs` drives the real `renderMap` behind a stubbed `fetch` — a copy of the renderer in the test would only ever agree with itself.
- **Two ways to get a bulb on the map, for two different moments.** `POST /api/map/import-lifx` adds every unmapped bulb at once and is the right button exactly once; the picker (`GET /api/map/candidates` + `POST /api/map/add-lifx`) adds one at a time with a role and a zone chosen as it goes on. Six lamps dropped on the middle of the floor plan named after their serials is not a map.
- **Panel rows say plain words, and a pile of lights is one dot.** The Light Map's label carries its own dark halo and light ink in both colour schemes. Lights within a dot's width are one dot with a count that opens a pick list, and the picked light is drawn beside the pile so it can be dragged out. Labels try under then over their dot and a light that fits neither is folded into a wider pile; piles are named by their shared zone or "first name +N". The list is grouped by zone with a one-line note on what a zone does, a count of lights still on the import spot (exactly 0.5, 0.5, which a drag never produces) and a search past eight lights; tapping a row scrolls the selection bar into view, and Remove lives only on that bar (two taps). Zones are suggested from the names (words every name starts with are skipped, the next word is the zone when two unzoned lights share it or the zone exists; "Den2" reads as "Den"; never a zone that would hold every light; nothing is saved until accepted), and a map where most lights have no zone says so above the suggestion. The found-but-not-mapped count carries its own Add all button.
- **A control that answers on `pointerdown` moves the page under its own tap.** A pile opens on `click`; a dot still selects and drags from `pointerdown`. Drawing the pick list on `pointerdown` pushed the floor down and let the tap's `click` land on one of the list's own buttons.

## Panel lists and controls

- **A list says its verdict first, and a control appears where there is a choice.** A list opens with one line that answers "is anything wrong?" and does not repeat the same words on every row. The Lab bulbs open with one line ("2 of 24 checked, all fast"), fold the unchecked ones, say "Fast, 42 ms, no loss" with the jargon behind an info toggle, and offer one sequential Probe all unprobed. A party song gets the show picker only when `/api/library`'s `show.versions` is above one; Party's show column is one control on every row, switched off where there is no choice, under a "Which show" header, and a party row's show slot says "Latest" (a row's `display: grid` must be matched by the fold's `display: none` at the same specificity). Library folders carry their source from `/api/library` (`main`/`option` are configuration, only `picked` has Remove; removing a missing folder must not need the folder to exist), give each row one status, name the missing folder and the fix that applies to where it came from (Remove only for a missing folder ticked in the panel, Configuration for one from the options), are one summary line, and empty folders share one line with no button. Effect parameters are labelled in words with their unit (`PARAM_WORDS` in app.js; an unknown key still reads as words), and an effect with no lights ticked says it drives every light it suits, which is what `resolve_fixtures` does with an empty list. Speaker pickers use the friendly name `/api/calibrate/profiles` carries.
- **The Shows list folds and says its verdict once; a tap goes where it opened.** The list opens with one line ("21 of 23 songs have a show ready · 1 played so far"); a row says only what sets it apart ("played 3 d ago" from `last-played.json`, written by the conductor where a show starts, not for the beat test), and the build facts ("Written by Claude · N cues") sit in its ⋯ menu. It shows eight songs and a Show all button (the open song is always shown), and tapping a song scrolls to its editor, which is below the whole list and one line until a song is opened. The intro names what ▶ Play and ⋯ do, and the Claude controls (mood and Check Claude) sit under the list with one plain line saying what they are for. The Library counts the folders its rows name and its unanalyzed tracks, and Shows counts against the Library's total.
- **A ⋯ menu is a row of the list, never a floating box.** The menu is a sibling line under its row (`moreToggle`/`.more-menu`, hidden until the ⋯ button opens it) and takes the full row width; an absolutely placed menu draws over the next rows' buttons on a phone. The commonest action stays on the row and the rest go behind the one ⋯.
- **A pair has to read as two different rows, and a default is a choice made for somebody.** Rows lead with the length, and `findCopies` pairs two files with the same tidied name or the same tempo and length, and also two untagged files whose tidied names match *and* whose tempo agrees within 1.5% (a clip keeps the tempo and loses the length; a shared name at another tempo, "Intro" in two albums, is another song); `copyNote` says which row is the clip and which the full song, with the other's length and folder, on Library, Shows and Party. Short clips are listed after the full songs under one heading on Library, Shows and Party (`findClips`: under 90 s, or in a folder where most analyzed tracks are; never the file's name). A missing folder is a ⚠ only while nothing holds music; the old BRigt click track (`/media/brigt/calibration.wav`) is excluded like the current one, and the fold says "Show folders" instead of a bare ▾. The beat test's picker starts from the bulbs this browser last tested with (`localStorage`, a convenience only) or none, never every bulb in the house; Test mode's bulbs are one closed fold per Light Map zone with a tick for the zone, and its Start is off until a track, a speaker and a bulb are chosen, with a line naming what is missing. Shows' speaker picker defaults to the same "Best calibrated speaker (name)" as Party (`bestSpeakerLabel`, the client mirror of `calibration.best_entity`; empty is sent as no speaker and the server picks), or the one this browser last played on.
- **A fold that does not look like one, and a default one tab has and its neighbour does not.** `.info-toggle > summary` is `display: flex`, which drops the browser's disclosure triangle, so the summary draws its own ▸/▾ in azure (not on folds that name themselves with `.fold-label`). `.demo-controls label` stacks caption over control, so `label.fx-flag` inside it is a row again, or a tick box sits above its own word. The phone tab strip fades each edge that has more tabs past it, brings the open tab clear of the fade on open (`tabEdges`/`revealTab`), and carries a ‹/› button on each such edge (`tabsBack`/`tabsOn`, above the strip with `z-index`, since the strip is positioned and later in the DOM).
