# Morph specifics

Morph's service, files, Tells, salience, cases, learning loops, frontend and measures.

Part of the project notes (see `CLAUDE.md` › *Where the notes are*). Read this file before changing what it covers; add a note here, not in `CLAUDE.md`.

- **Morph is part of brAIn since 4.0, and the halves kept their jobs** (docs/design/brain-morph-merge.md). The service, `brain/morph/service/morphd.py`, runs in brAIn's container (run.sh's `start_morph`, root, loopback health on `127.0.0.1:8096`, restarted by its own watch loop) and is the only writer of `/config/morph`; it reads brAIn's switches (`/config/.brain/features.json`) every few seconds and does nothing while the Morph dashboard is off — `main` waits before `bootstrap`, the loops skip, a request is answered `OFF_ERROR`. Its state is `/data/morph` (the retired add-on's `/data` is not reachable, so its settings and scorecard start again). The panel half is `custom_components/brain/morph/`, set up by the `brain` integration (`hass.data["brain_morph"]`, the websocket names `morph/*` and the static paths unchanged); the sidebar entry is brAIn's shell (`frontend/shell.js`), which mounts `<morph-boot>` as the Home tab with `shell = true` (Morph then draws NO bar — brAIn's header is the one header, carrying Morph's Edit/Done/YAML through `morph-chrome` and `chromeAct`, and drawn in Morph's theme; panel.md has the contract) and alone, full height, for somebody who is not an administrator. `--morph-h` is the height the shell gives it. Talk to the service by file IPC under `/config/.morph` (`requests/` → `responses/`, with the mirrors `dashboard.json` and `state.json` read directly), from the integration (`bridge.send_request`) and from brAIn's panel (`panel/morph_service.py`, ⚙ › Dashboard's kinds only). Writes are `morph/request`, `require_admin`; `WRITE_KINDS` in `websocket.py` and the `kind ==` branches in `morphd.handle` are held equal by `tests/test_morph_addon.py`. `learning` and `report_code_issues` are brAIn's switches (Learning loop, Development loop), read on every `settings.load`; a stored value for either is ignored. Morph's Settings page is gone: ⚙ › Dashboard draws the service's mirror, and Morph's "See the changes" opens it through the shell (`brain-open`). With Personality on, every region's HTML goes through `speak` (never inside a `<textarea>`), and `who()` reads `features.name` first.
- **Every change is one commit, and nothing else is history.** `gitrepo` serialises git under one lock (a tell's commit, a save and the watcher are different threads), authors each commit by who made it (`person`, `brain`, `learning`, `outside`, `morph`), commits a hand edit as *Edited outside Morph* before anything else touches the tree, and reverts or restores as a NEW commit so an undo is undoable. `head()` and `log()` both answer 12-character ids — they answered 12 and 7, so the commit a Tell reported was not one the History page could name. `/config/morph` is chowned to brAIn's `claude` user after each commit so brAIn's next edit is an in-place write. brAIn is told never to run git there (`ha-context-gen.sh`'s Morph section and `defaults/AGENTS.md`).
- **A file that does not parse is somebody mid-edit** (`store.publish`'s `held`). The mirror keeps the last dashboard that read and carries the parser's line; the panel shows it above the notes. The revision is the hash of the file's text, so a fix is noticed the moment it is saved.
- **Ids survive a round trip** (`store._pre`, `normalize`). Undo, notes, suggestions and the usage log key on card and section ids, so `dump → load_text → normalize` is the identity; a fresh id on every save made every save read as a new dashboard (and `f_f_…` was the first cut).
- **A Tell's result names every place it could have reached** (`whatHtml`: Dashboard, Home Assistant, Morph's code, brAIn's memory, GitHub), each with *Not changed* / *Nothing sent* when untouched, because "it only changed the dashboard" has to be read, not inferred; the composing box says the same before Send. **A choice that is the person's is `question` in the answer** (`tell.clean_question`: two or three `{label, request, home_assistant}` buttons, a literal `true` only), and a value a card works out from other sensors is NOT one of them: brAIn makes the template sensor and shows it (AGENTS.md). `tell_answer` starts the next tell from the option STORED with the tell, never from words off the wire, with scope `house` only when the pressed option said so; one answer per question.
- **Tell acts at once, and the commit is what makes that safe** (`service/tell.py`). A Tell is a `tools: full` brAIn task through brAIn's task folder (claimed by rename; 30s unclaimed is "nothing is listening" and the task is withdrawn so it cannot run an hour later); when it answers, Morph commits the dashboard half as ONE commit and Undo reverts exactly that one, then sends brAIn a follow-up Tell naming the house changes to put back. `protected_entities`, the action gate and brAIn's edit snapshots hold whatever the prompt says.
- **A Tell starts with a picture, and is about the dashboard** (`frontend/snap.js`, `morph/shot`, `tell.build_prompt`). `snap.prepare` clones what was held SYNCHRONOUSLY in `openTell` (holding a card opens it, and the picture has to be the card as it was), with computed styles inlined against the parent (inherited) or the tag's default (the rest), shadow roots and slots flattened, canvases/images as data URLs and Morph's two fonts embedded, then `render()` draws it through an SVG foreignObject; an OPEN card is photographed by its `[data-face]`, never the tile with the editor cut out. The integration files the PNG under `/config/.morph/shots` (admin, PNG magic, under HA's 4 MB websocket frame, owned by UID 1000 with owner-only modes so brAIn's `claude` user can Read it and nobody else needs to) and the prompt puts its path BEFORE the YAML; a shot id is checked for shape and existence before it becomes a path, and a picture that could not be taken is said, with `viewText` (the element's text through every shadow root) sent instead. The scope is `ui` unless the caller is Undo's follow-up (`scope="house"`): `morphd` never reads a scope off the wire, and either scope does the whole job: the Home Assistant changes the result needs (a template sensor, an automation, a helper) are made too and listed in `home_assistant` for Undo. House facts go to `remember_fact`, never `LEARNED.md`. A `code_issue` in the answer is ASKED ("send this as an issue?", `tell_issue`), never filed by the model.
- **What brAIn is doing is read off brAIn's own hook** (`brain/scripts/brain-task-progress.sh`, `tell.progress`/`_follow`/`describe_call`). The automation listener exports `BRAIN_TASK_PROGRESS` per task and the headless settings run the hook on every tool call; it is sh, exits on its first line without the variable, prints nothing and records a call's subject, never its content. Morph turns lines into steps (repeats folded, to-do bookkeeping dropped, capped with a count) and publishes running tells as `activity` in `state.json`, so a tell stays visible after its box is closed. The tell box's elapsed time is written by a one-second tick into `[data-since]` spans and never into the compared HTML, and only the newest step has `rise`: a box rebuilt every second replayed its blur-in for as long as brAIn worked.
- **A Tell is read back, never taken at its word** (`tell.read_back` / `describe_change` / `outcome`, `ON_PUBLISH`). Reported as *"it says it's making changes to the dashboard, but none of them are applied"*: a finished Tell ended on brAIn's own summary whether or not anything under /config/morph had moved, and the mirror waited for the watcher's next pass. When brAIn answers, Morph diffs dashboard.yaml at the Tell's base commit against the file now and lists what a person would see (`shows`), republishes the mirror at once through morphd's own `publish` (`tell.ON_PUBLISH`, since tell cannot import morphd) and records its `revision`; the panel always reloads on done and offers **Refresh** while its mirror is behind. Three endings are said in words: nothing changed (`unchanged`, *Nothing on the dashboard changed* with brAIn's summary quoted), a rewrite that changes nothing on screen, and a file that no longer reads (`failed`, *Not applied*, the commit kept so Undo reverts it). The phase is written only with the final save, because a state file reading "done" is the panel's (and the tests') signal that the lesson and outcome have landed. brAIn's "changed" lines that name a Morph file (`_morph_file`) are not house changes — "dashboard.yaml" used to send Undo to brAIn to put back a house change nobody made. `greeting: false` hides the hello line; the prompt says a Morph dashboard is dashboard.yaml and never a Lovelace one.
- **Morph is brAIn's face, and the page is ONE salience list drawn five ways** (`frontend/salience.js`, docs/design/morph-vision.md §4–§11). Every card and every case gets inputs (deviation off brAIn's `feed.json` normals and door habits, urgency, progress, habit, recency, viewer), one score (`score`), and a band with hysteresis (`BANDS`, `bandFor`: Now ≥.75 leaving at .60, Lead ≥.45/.35, Shown ≥.20); the verdict's coloured first clause, the Now layer (≤3, ≤2 under 480px, deduped by entity so a lock carried by two rooms is lifted once, `twin`), the room order and fold, the room line and the floors' summaries all read that one result, so they cannot disagree. Three rules keep it calm. **It is pure** — `compute(items, ctx, prev)` reads only what it is handed, so `tests/test_morph_vision.py` drives it under node. **The page takes a new result only at a quiet moment** (`quietMoment`: no pointer down, nothing open, 1.2s after a touch, 600ms after a scroll, 8s after the last rearrangement) unless something urgent arrived, and a period change (night/away) skips only the spacing — `maybeApply` keeps `salState` (newest) apart from `salApplied` (what is drawn), and a because line reads the newest. **At night Now holds only what the night floors lift** (an open closure or unlocked lock, an urgent trip, a rose case, a pin): the vision's test is *armed at 11:30 PM with one unlocked lock shows exactly one card*, which `measure-morph`'s `night` asserts. A lifted card is MOVED (`engine.moveTile`, travel without a fade), never copied, and its room keeps a trace. A feed older than its own `stale_after_s` is used and said; past a week it is not used (`feedHealth`), and nothing in a because line names a measurement brAIn did not send.
- **brAIn's cases are drawn where their subject is, and a reply is read, not pressed** (`frontend/cases.js`, `ws_case` → `requests.write_morph_request`). The one list is brAIn's (`/config/.brain/morph/cases.json`, `_brain_feed` in websocket.py); Morph keeps none. A card is the claim, the ask, the last three turns of its thread and a reply line (16px, `.morph .replyin` — `.morph input{font:inherit}` outranks a bare class) plus the presses; no Yes, No or Wrong, because brAIn's interpreter reads the words. **A card reads as brAIn's Needs you reads it** (#452: *"wherever I'm looking at things … it feels like the same surface"*): it said *To Do* where brAIn says *Add to To Do*, wore no chip, dropped the detail and kept ids where brAIn shows names. It wears brAIn's one chip word (`caseChip`, `answers.chip`'s rule for a row with no `chip`), the title and detail with friendly names for ids, and `casePresses`: the row's own `answers` labels in brAIn's order, with Snooze put back before the ending that waves a card away because cases.json leaves it out; Check again and Ignore are not offered until brAIn's queue takes them from Morph. `tests/test_morph_case_parity.py` builds a house's cases with brAIn's own `answers` and `morph_bridge.case_row` and draws them with `caseFace` under node. Morph's words name the assistant by the household's name (`MorphPanel.who()`, `brain.who()` in the service, off `/config/.brain/personality.json`), never a second name beside brAIn's. Two fields only Morph can act on ride back (`followReplies`): a brAIn turn's `tell` (a page change the reply also asked for, which brAIn cannot run — run once, only on the page that sent the reply) and `said` (brAIn's last word on a case the reply ENDED, said as the card leaves, because the row took its thread with it). A family tablet shows a question's reply line only after a tap. To Do is brAIn's to-do list as a section (`ws_todo`: done, drop, snooze 1–60 days).
- **Every task Morph writes says it came from Morph** (`brain.ORIGIN`, `"origin": "morph"` on every task `brain.submit` writes — a Tell, a conversation, a learning pass, a code redo — and nothing else in the service writes into the task folder): brAIn lists Morph's conversations under its own pill (#427), and a field is the one thing it can read without guessing from a prompt's wording.
- **A person's words reach brAIn whole, from the first character** (`wording.fit` / `clip`). Words over the bound used to keep their END behind "(the start of this message was cut to fit)", so a long request reached brAIn — and brAIn's chat — missing its opening, cut mid-word (#428). The words are never cut now; only the context sent beside them gives way, on a line break (else between words) and marked, or is left out with a sentence saying so. Text Morph itself writes into a request (a suggestion's change, a question's option, a summary handed back as history) is cut between words with an ellipsis (`wording.clip`).
- **A conversation is brAIn's chat by task** (`service/converse.py`, `brain.submit(kind="conversation", session_id=)`). Ask's `conversation` answer starts one: the automation listener runs it on the chat channel, resumes the session the last turn used, and does not claim it in `run_sources`, so it is the person's own conversation in brAIn's Ask tab too. The state rides beside the Tells' (`/config/.morph/tells`) so the panel follows it with `tell_status`; a session id off the wire is matched against `SESSION` before it reaches the task.
- **Ask stacks: every question keeps running and its answer stays** (`s.asks`, `askAdd`/`askSet`/`askDrop`, `answerHtml`; the owner: *"make sure that when asking multiple commands everything keeps running and the answers stack up"*). Ask had ONE slot (`s.ask`), one conversation (`s.converse`) and one poll timer: a second question overwrote the slot and cleared the first poll, so the first answer never appeared, although the service went on running it. Each question is now its own entry with its own conversation id and poll, newest first, the last `ASK_KEEP` (5) kept (a finished one is dropped before a running one); `[data-ask]` is `aria-busy` with a pulse while ANY is in flight; a tap outside folds only the finished ones; and the session is resumed only when no other conversation from the page is in flight, because two turns resuming one session would race for it (the second starts its own; whichever lands last names the session the next question resumes). The service runs them in parallel: `converse.start` gives each its own asyncio task and id, and the automation listener runs every task file as its own background process (`process_task &`), so nothing queues behind the first. **A Tell replaced while it runs is parked, not lost** (`parkTell`, `tellsAway`): `s.tell` is a setter, and a tell it stops showing while brAIn is still at it (another Tell, the box closed) is polled until it lands and then said in the strip at the top with **Show**, which opens its box again with Keep and Undo; the activity strip used to forget it the moment the service stopped listing it as running. `measure-morph`'s owner block asks two questions back to back (the fixture's `__convEcho` answers each by name and a "slow" one later).
- **The page updates in place** (`frontend/morph-dom.js`): `morph(el, html)` keyed by `data-key`/`data-member`/`data-k`/`data-tile`/`id`, skipping custom elements, a hosted Lovelace card (`data-ll`), `data-morph-keep` and a focused input, keeping `<details>` open and a spinner's phase. The board's own removal pass touches only `fl:`/`sec:`/`g:`/`t:` keys: it once removed every `[data-key]` it had not just drawn, which took the To Do rows and a range input's key with it.
- **A resting spring outlives its element** (`engine.overlaps` / the prune in `layout`). `run()` drops only LIVE springs whose element has gone, so leaving Edit left each "Add section" ghost's spring where the ghost stood and the audit reported the room that moved there as overlapping it. `overlaps()` compares only sections in the model and on the page, and `layout()` forgets any spring whose element is disconnected. `tests/test_morph_house_reports.py` drives `Engine.overlaps` under node.
- **A card file that changes is defined once per PAGE, and the page's record lives on the window** (`util.cardPage` / `guardDefine` / `loadCard` / `cardFailure`). A new `?v=` import re-runs the module and its `customElements.define` throws; that is the browser keeping the old class until a reload, so it is a **Reload** toast and never a fault report. The record of what was loaded was module-level, and an update serves Morph's own modules from a new URL, which runs them again without a reload: the fresh, empty record read a card file running again as its first run, and four cards' "name already used" were filed as four faults. The record is `window.__morphCardPage` now, `guardDefine` skips a define of a name the page already has (the element already registered goes on drawing, and the rest of the file still runs), an import in flight is shared, and a failure is reported by its CAUSE with the card's name in the detail, so five cards failing for one reason are one fault. AGENTS.md's example guards its define. `measure-morph` serves a card file twice and fails on a report; `tests/test_morph_card_loader.py`.
- **A dashboard change is a Tell wherever it is typed, and brAIn decides which it is** (`morph/ask` → `/config/.brain/morph/asks/` → brAIn's interpreter on the `morph` surface → `answers/<id>.json` `{do: done|conversation|tell_dashboard|tell_code|fallback, say}`). Outside Edit the Ask line used to go to the house's conversation agent, which cannot write /config/morph and answered that it was making the change. The interpreter's `dashboard`/`code` kinds are the Tell; `conversation` is a brAIn chat task (`converse.py`, below); `done` is a rule or a fact brAIn filed; `fallback` (brAIn could not read it) keeps the old `DASH_CHANGE` word test and then the house's agent. Every answer offers **Change the dashboard instead**. `ws_ask` waits 40s for brAIn's answer and says `fallback` past that, because a line nobody answers is worse than the old path. The other half of the original report was brAIn's own: `brain-protect-hook.py` refused any YAML naming a protected entity, a dashboard names the locks, so `is_morph_dashboard` exempts that one file, on real paths.
- **A card file gets a second fetch, and a copy's card type is Morph's** (`util.importWithRetry`, `morphcode.card_types`). A custom card whose module FETCH failed (Chrome, Safari and Firefox each word it differently, `fetchFailed`) is fetched once more on a fresh URL before it is reported, and a card whose code threw is never run twice. A type an ACTIVE copy of `cards.js` adds to `TYPES` is kept by `store.normalize` rather than wrapped as a Lovelace card nobody can draw; a paused copy's types are not, because the page is not running it. `history.climateTargets` reads anything but a list (a fetch that answered `{error}`) as no band. `tests/test_morph_house_reports_two.py`.
- **Ask is the one door to a Tell outside Edit, and the mark is only the brand.** The hover mark, the opened card's mark and the section title's mark were three second doors beside Ask, and the vision folds them into it (§13.3); `test_morph_house_reports_two.TestARoomIsToldAboutThroughAsk` holds that none comes back. `MARK` in util.js is still the drawing (`branding/morph/`, the README's Morph section): squares and tiles are the mark alone and carry no BR ligature, which `test_no_asset_is_the_gable_alone` exempts and `test_morph_squares_are_its_own_mark_and_no_roof` holds; the wide lockups keep the ligature with the mark where the roof stood.
- **"What do you want to fix?" is Ask, and Morph's own reports are still a ledger** (`devloop.note_request` / `mine` / `withdraw`). The Settings box went with the vision (words about Morph are a Tell about Morph's code, which Ask routes); the request kinds `report`/`report_withdraw` remain, so a report already filed can be listed with **Take back** until brAIn's ack is newer than it, and `rows()` still gives a person's report its own body. Nothing is sent while `report_code_issues` is off.
- **Two learning loops, the way brAIn has them.** Loop 1 (`service/learning.py`): the panel logs uses (`USAGE_KINDS`, equal in the integration and the service), and a scheduled brAIn pass — `tools: read_only`, `scheduled: true` so brAIn's gates apply — returns at most five suggestions and the COMPLETE lesson list. Suggestions are **brAIn's cases** (`learning.sync_brain`, on morphd's tick): each open one is filed once as a `morph_case` request on brAIn's queue (`case_body`, key = the suggestion's id) and withdrawn when it ends here; brAIn publishes how it ended in `cases.json`'s `ended_morph` (`accepted|declined|dismissed|todo`, read once per `key@at`), and `accepted` starts the Tell (`_start_suggestion`, settled by its tell: a failed run reopens it) while `declined` keeps the reason as evidence for the next pass. Morph keeps no list of its own on the page, and brAIn writes nothing to memory about a Morph suggestion. **It is about the dashboard only** — brAIn learns the house — so the schema's `kind` is `dashboard`, the prompt asks for no Home Assistant changes and no house facts as lessons, and carries AGENTS.md's design rules as text, because a `read_only` task is denied Read and was being told to read AGENTS.md. The pass's `code_reports` become suggestions of kind `code` (**Send as issue**, `decide(…, "send")`), never faults filed on the model's word. Lessons live in `LEARNED.md`, committed as `learning`, read by every Tell and pass. A pass with nothing new (`fingerprint`) spends nothing, and the fingerprint is written only by a pass that ANSWERED: written up front, a failed pass marked the evidence read and every later pass skipped. Loop 2 (`service/devloop.py`): Morph's own faults — a card that threw, an overlap at rest reported by the panel's `audit()`, an answer from brAIn Morph could not read, and what somebody chose to Send as an issue — are a ledger (brAIn slow, signed out or paused is not Morph's fault and files nothing) keyed on the digit-folded `where|what`, published to `/config/.morph/devloop/outbox.json` in brAIn's row shape with `where` starting "Morph". brAIn's devloop reads it as the `morph` stream (`streams.morph`, `server._devloop_morph`, which writes `ack.json` back so Morph's Settings can say when it was picked up), files it with `devloop:morph`, and the fix-from-house skill fixes it under `morph/`. `None` from the reader is "Morph absent", never an empty pass.
- **Morph's service faults are Morph's own to report** (`devloop.note_exception`, called from `morphd`'s request loop, `_one`, the watcher and the tick). The ledger held what the PANEL reported (a card that threw, an overlap at rest) and the service's four `except` blocks logged and moved on, so a request loop failing on every poll was in the add-on log and nowhere brAIn's `morph` stream could read. Each is a row now: the exception's type, the deepest frame in Morph's own code and the message as `what` (digits fold in the fingerprint, so a line that moves is the same fault), the traceback as `detail`, under the Development loop switch (⚙ › Features) like every other row. `tests/test_morph_service_faults.py` raises inside a service module and greps that every handler in `morphd.py` files what it catches.
- **A per-house addition to a built-in card is an option, not a copy of Morph's code** (`cards.js`'s `climateActions` / `climateFoot`, `morph-panel.js`'s `detailCard`). A house got script buttons on its thermostats and a performance chart folded under them by brAIn copying `cards.js` and `morph-panel.js` into `/config/morph/frontend` and patching them, and a copy pauses on every Morph update that moves any module. `options.actions` on a `climate` card (up to four scripts, buttons or scenes; a running script reads as pressed) and `options.detail` on any built-in card (a Lovelace card mounted only while the card is open, kept in `llCards` so reopening does not reload it) are the shipped form. The actions take the place of the ruler's end labels, with padding cancelled by negative margins, because same-row tiles must stay one height and a button still needs its 40px target. `tests/test_morph_climate_actions.py`, `measure-morph`'s detail block.
- **An opened card offers Home Assistant's own pages** (`moreInfoHtml`): **Details** fires `hass-more-info` (bubbles, composed — the panel is not in an iframe, so Home Assistant's own dialog opens) for the card's entity, the tapped member, or a one-entity list; **Device page** (admins) pushes `/config/devices/device/<id>` and fires `location-changed`, HA's own navigate. Not on a hosted Lovelace card, which opens its own.
- **Opening Morph paints at once, and a reload is something Morph says** (`frontend/boot.js`, `static.stamp` / `boot_source` / `stamped`, `updateHtml`). Home Assistant creates a custom panel's element only once its `module_url` has finished running, and paints `--primary-background-color` until then (`ha-panel-custom.ts`). boot.js awaited the whole panel, so the page was blank (white in a light theme) for seven modules' worth of round trips, each a `no-cache` revalidation discovered one import level at a time. The registered element is now `<morph-boot>` (`ELEMENT`): boot.js defines it synchronously, it draws the dashboard's outline in the theme the panel last used (`localStorage['morph.theme']`, written by `render`), and it mounts `<morph-panel>` in its shadow root once loaded, appending first and setting properties after so `morph/load` runs once. The outline lifts on the panel's `morph-ready` (`readyOnce`, at the first render with data), or after `READY_AFTER_MS` for a copy written before the event existed. static.py writes `STAMP` and `MODULES` into boot.js. `STAMP` is a hash of which file answers each module and that file's size and mtime, so it moves with an update or a copy coming in or out of use. The modules are `modulepreload`ed and imported under `s/<stamp>/`, which is served `immutable` only while the stamp is current, read between two stamps so a file written mid-read is never cached under the wrong name. A stale stamp still gets today's file with `no-cache`. An unstamped boot.js (a test, or an older integration that still creates `<morph-panel>` itself) keeps the top-level await, and `MorphPanel`'s constructor re-applies properties set on the bare element before it was defined. `morph/load` returns `code` (the current stamp) and `integration` (the running VERSION). `updateHtml` offers **Reload** when either differs from what this page loaded, and asks an admin to restart Home Assistant when the add-on is newer than the integration. `measure-morph` delays every module 1.5s and fails on no shell, no outline, a white outline, an outline left over the dashboard, a module outside `s/<stamp>/`, or any of the three bar states missing. It failed both shell checks with boot.js awaiting the panel again.
- **The frontend is plain ES modules with no build** (`frontend/`), served at `/morph_static/<VERSION>/` so an update is a new URL. `engine.js` is the prototype's layout engine (springs, masonry, rows grouped by height kind `hk`, open-in-place, make room first); an opened card keeps its column when the row has room and otherwise its right edge. `history.js` quantises every window to the minute and keeps the last answer per family (`LAST`) while a new one loads, because a chart that blanked on a minute rollover changed a card's height mid-motion and showed as an overlap. The style module is imported as `STYLES`: importing it as `CSS` shadowed the global `CSS.escape`. Custom card code brAIn writes lives in `/config/morph/cards/*.js` and is loaded with its mtime in the URL.
- **Morph can change itself, one module at a time** (`service/morphcode.py`, `custom_components/brain/morph/static.py`, `frontend/boot.js`). The complaint was brAIn answering that Morph's header "is Morph's own code, and I can only change the dashboard's files". The whole point is that nothing about Morph is out of reach. So brAIn copies a module from `/config/custom_components/morph/frontend/` (`paths.SHIPPED`: what HA serves; read-only) to `/config/morph/frontend/<same name>` and edits the copy.
  - **One commit, recorded.** `gitrepo` calls `morphcode.record_bases()` before every commit, so the copy goes in with `.base.json` saying which version of Morph's file it was last written against (re-recorded whenever the copy's own hash moves), and Undo puts both back.
  - **Paused by an update.** An update that moves Morph's own file under a copy PAUSES it (Morph's own is served), because last release's module beside this release's others is how a panel breaks. Writing the copy again un-pauses it. **So does an update that moves any OTHER module** (`others` in the record, every shipped hash at write time; `status()` reports `why: others` and `moved`): a copied morph-panel.js imports engine.js, and pausing only on its own file let it run beside a new engine. A record from before `others` existed is filled in on the next commit rather than guessed. **A copy that reads the retired `personality.js`, and that file itself, are paused whatever the record says** (`morphcode.RETIRED`, `why: personality`): a house that customised Morph before the personality was brAIn's kept reading the old file through an accepted copy of morph-panel.js, whatever Morph shipped (#391); Settings › Personality says in one sentence to remove it, the old file offers Remove and never Update, and making the copy again tells brAIn to start from Morph's own and leave the file behind. A code-redo tell brAIn ANSWERED is `morphcode.accept`ed before the tell's commit — brAIn either edited the copy or judged it fits — so Undo takes the record with it and the copy pauses again; a failed one stays paused, and "no longer needed" means brAIn deletes the copy. **A merge brAIn would not guess at is a `question`** (`redo_words` tells it not to write the copy when the update rewrote the code the change was in): an answer carrying one is NOT accepted, so the copy stays paused until a button is pressed, and each option's request names the whole merge with its paths because it is sent on its own; the answered tell is kind `code` too and is accepted when it finishes without a question.
  - **One verdict.** `code.json` (`morphcode.publish`, every `publish_state`) is the one verdict the integration reads. `static.pick` serves a copy only when that says `active`, Morph's own under `shipped/`, and never `boot.js`. Every answer is `no-cache`, because one URL can now be two files.
  - **Making a paused copy again is a press with a box, and a three-way merge.** `code_redo` starts a Tell of kind `code` (`REDO_PATH`), and the panel opens brAIn's box inside the paused note, which stays until the box is closed. Its first tell went out with only a header toast and an unchanged note, which read as "nothing happens". A second press while one runs returns that one (`already`). The press is held in `this.s.redo` until the service answers, never written onto the button: the panel redraws on every state change, and 0.5.2's in-place "Handing it to brAIn…" was redrawn back to Make it again at once. A refusal stays in the note with Try again. `record_bases` keeps Morph's own file each copy was written against at `frontend/.base/<name>` (`kept_base`), so `redo_words` hands brAIn the original, the copy and the new release, plus the commits that touched the file. The kept original is not a change: `code_files` skips anything below `frontend/`'s top level, and the issue patch excludes `frontend/.base/`.
  - **A Tell's house facts ride in its answer** (`facts`, `tell.queue_facts`). A Tell is a task run, and brAIn's action gate refuses `remember_fact` there because the words asked for no memory. Morph writes them to brAIn's memory inbox as source `morph`, only when `/config/.brain/memory` exists.
  - **A broken copy is not a blank page.** `boot.js` (the `module_url`) imports the panel and, if that throws, imports `shipped/morph-panel.js` and leaves `window.__morphFallback` for `codeProblemsHtml`.
  - **Then it asks.** A Tell whose commit touched `frontend/` sets `state.code`. The box offers **Reload to see it**, and asks to open an issue whether or not brAIn filled `code_issue`, with the patch attached (`gitrepo.diff`; `devloop` no longer fences a detail that carries its own fence).
  - **The rest.** A code suggestion's Do it is a Tell. `code_reset`/`code_redo` are the Settings and note presses. `measure-morph` serves a working and a broken copy through the fixture's `overrides`.
- **The prototype (`docs/design/morph-ui.html`) is the reference for how Morph looks, and `measure-morph`'s `design()` holds the parts that drifted once.** A strip's status line is quiet text and its colour lives in the fill and icon (`stripFace`'s tones are the prototype's: a fill strong at the left fading to the thumb, no tint behind a light, a switch the only strip that tints itself). A light group is span 2 and grows down. Notes follow a room's tiles. Coming up is `upcoming.js`'s strip, every class `cu-` prefixed because Morph's bare names (`.track` is the switch, `.mid` a 28px number) collide; it is a fixed reading point with the timeline dragged behind it, so the panel never rebuilds it under a finger or mid-glide (`upcFrozen`), keeps the cursor as a TIME (`s.upcAt`, null for now) so a stopped-on event stays under the line, and `measure-morph`'s `comingUp` drives the drag, a tap, a swipe, Now and the arrow keys. The Ask suggestions show only on `:focus-within` (a mousedown on one is prevented so Safari keeps the focus). The overlay chart (`history.readings`) draws a target band from the thermostats' own history (`timeline(..., attrs)`), their cooling/heating runs, a 138px label column that `overlayAt`/`overlayRest` repaint under a finger, an axis and the extremes as sparklines.
- **`tests/manual/measure-morph.mjs`** drives the real panel against `morph-fixture.mjs` (a fake `hass` answering every `morph/*` command, history, statistics, logbook, conversation and service calls) at 1440 and 400: no section or tile overlaps at rest or in any 30ms sample while 12 kinds open and fold, same-row tiles are one height, tap toggles, slide sets ~70%, the garage needs two taps, Edit → hold → Tell → Keep/Undo works, a case's reply becomes a turn, a reply that ends a case and asks for a page change runs that Tell and says brAIn's last word, a quiet room folds and opens on its name, and armed-night with the front door unlocked shows exactly that door (the tour turns `fold_rooms` off so every kind of card is on the page). It runs in CI's `layout` job when `morph/` changes.
- **The design rules a grep can check are checked on every change** (`tests/test_morph_design_rules.py`). The shipped frontend had drifted from rule 13 unseen: a light's name, a white swatch, a meter's day bars and a camera's name carried `title=` hover text. They are gone (a day bar keeps its words as `role="img"` + `aria-label`), and the test fails on any `title=` but an `<iframe>`'s accessible name, on rule 1's overlay constructs (`position: fixed` but an invisible measuring probe, `<dialog>`, `showModal`, `popover`, `alert`/`confirm`/`prompt`), on Morph's bar carrying a brand, ☰, ⚙ or Feed inside brAIn's shell, and on the design's numbers (springs K = 150, ζ = 0.82; 130/170 ms make room first; the three themes' `--bg`/`--surface` in `styles.js` and `boot.js`'s outline). `measure-morph`'s design block fails on any rendered element with a `title` outside a hosted Lovelace card.
