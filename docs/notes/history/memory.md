# brAIn: memory, facts, guesses and curiosity: history moved out of docs/notes/memory.md

What each rule in `docs/notes/memory.md` cost to learn. None of it is needed to follow the rules; it is here for the next person who wonders why a lock, a fold or a guard exists. Pointers to tests under `tests/` name files that were removed in November 2026 with the old suite; the rules they enforced still hold.

## memory.md and its one writer

- **Memory.** The panel's "File into memory now" press was cut by the redesign (⚠3): the queue files itself. Filed discoveries were once listed again under "already in memory", which left a permanent list beside a queue that was meant to read as empty.
- **A consolidation pass rewrites a whole document, and is budgeted like one.** At a 120s timeout it was a coin flip on a full document, and every loss reported itself as `Claude invocation failed (not authenticated?)` because stderr went to `/dev/null` and the exit code was never read: the queue never moved, the button never worked, and the log sent people to redo a working sign-in. The STDOUT finding was read off the 2.1.295 bundle (the text printer writes through the stdout writer); the pass read stdout as the answer and deleted it on failure, so a house's journal held six `crash` rows in a day reading `claude exited 1` with the reason thrown away. `TestTheConsolidatorLoadsNoTools` and `TestTheConsolidatorHearsTheCliItRuns` held it, the latter with a stand-in that answers the way the CLI does, where the older fixture wrote its error to stderr — the shape the code guessed. The tab used to poll the 19 KB knowledge payload every 2.5s for the outcome.
- **A lock file's existence is not a lock, and its mtime is not an age.** `ha-selftest.sh` (`brain doctor`) stat-ed the lock file's mtime and warned past 900s, which fired on every home that had not consolidated in the last quarter of an hour: a permanent warning about a memory system that was working, on a report whose whole value is that its lines mean something. The remedy it named could not clear it either — the file is under `/config` and survives the restart it asked for. The panel had it right from the start (`_consolidation_running()`). The test that was supposed to hold this asserted the *script* rather than driving it, so `tests/test_memory_learning.py` lifted `consolidator_lock_check` out of the real file, ran the old recipe on the same fixture to show it warning, and held a real flock from a subprocess for the cases that must still warn.

## The queue on the page

- **A queue's list and a queue's count are one read, or they are two answers to different questions.** The Memory tab's "waiting to be filed" counted the memory inbox while LISTING the facts ledger minus anything whose `ts` predated `.last_consolidated`. The ledger only holds what the *analyst* discovered, so everything else queued was counted and never shown: nine things waiting above four cards, and neither number wrong. The ✕ used to send a `FORGET:` request, which asked to strike a line the document mostly did not hold.

## Clean-up

- **Memory is reviewed on a press, and a removal is a proposal like any other** (`panel/memory_cleanup.py`, Knowledge › **Clean up**). That was the first shape of the clean-up: every removal waited for a press. The plan's section 0 (no human in the loop) changed it, so `wrong`, `duplicate` and `stale` removals now apply without the press and only `useless` and `error` wait for one. Why it exists: memory only grew; nothing read the whole document and the facts store and asked whether a line still deserves its place, so a replaced device, a wrong guess, a one-off evening and brAIn's own bookkeeping were handed to every run as true. `tests/test_memory_cleanup.py` drove the runner and the routes with only `run_analyst` and `_consolidate_now` stubbed and asserted memory.md was not written by the route.

## The facts store

- **A facts store under the document, and the document stays the one thing you edit.** Every run used to be handed the whole 30 KB document whether it was about the kitchen or the boiler. The directory rule was found by the first full-suite run: a dozen fixtures patched `MEMORY_INBOX_DIR` to a temp directory while the scheduler's ingest wrote their queues into the real `/config`, where `test_memory_prompt_budget` then read them back as the retrieval block instead of the whole document it was asserting on.
- **House › What it knows is the teach box and this list and nothing else**: chips were Rooms · Devices · House with no counts, the source and **See the run** sat in a row's detail behind a press, and forgetting was **⋯ › Delete** after a confirm. The brief, the measurements, the memory document and its queue left the pane then (their loaders stay in `app.js`, guarded on their markup); the document and its queue came back as a fold when ⚙ › Memory was retired. The Knowledge browse rule replaced the chips and the ⋯ (kind pills with counts, Delete a bin on the row).
- **The document is the curated truth, and the store answers to it.** `facts_store` ingested every inbox line it saw and nothing a person did to memory reached it, so a forgotten line kept being handed to triage, the Resident, the brief, the weekly report and every card — the store most panel runs read since 2.2, curated by nobody. The first cut of the reconcile took its digest before its own write, so the write moved it and every tick ran the pass again.
- **A machine's reading of one moment lives two days.** "Moved across 69–72 °F in the last 12 hours" and "frozen right now" were handed to every later run as standing facts.
- **The store is repaired once per rule set and per amount of context.** `tests/test_facts_filing.py` drove each filing rule through the real inbox sweep and the real reconcile.
- **Bounded stores: the knowledge ledger keeps fingerprints and lets bodies go.** The ledger was capped by position and its questions list dropped the oldest question outright at 200, which made an old question askable again. `MAX_SEEN` was raised to 5000 for it.

## Knowledge on the page

- **Knowledge is browsed by what a fact is about.** A run files under the area id it guessed, so the rail read "Laundry, laundry room" and "Irrigation, Irrigation" before rooms were folded. *Taught by* and the sort were selects, then pills, then selects again; Delete was a ⋯ before it was a bin.
- **A subject is said in household words, and an app's world comes after the house** (#1301). A Minecraft choice-pad fact (`minecraft_facts`, subject `minecraft:companion` plus `person:<name>`) led Knowledge's newest-first list with chips reading `minecraft:companion` and a lower-case name, and `subject_kind` counted it a Device. On a phone the Taught by picker was half the row ("Taught by: Any…").
- **What each run is handed is said on the page, read off the code that hands it.** The owner: *"It's not clear to me what is imported on each new conversation vs what's in knowledge."* The answer was spread over six builders and no screen. `tests/test_context_map.py` failed on a read-only tool with no group, planted a token-shaped string and the document's lines to assert neither left the route, and pinned the numbers named for other processes against their source.

## Guesses

- **Dismiss on a question is a snooze the hypothesis store understands.** `/api/findings` used to hand a sleeping guess back as a loose card.
- **A guess answered in Home Assistant is a request, not a write.** `brain.answer_question` appended to a file nothing read and queued the typed answer as a high-confidence fact, so a "no" became knowledge and the guess stayed open. The docs once named a `brain.case` service that never existed.

## Curiosity

- **Curiosity asks for room before it spends, and a refused guess is deferred rather than settled.** `_ask_why` spent a Sonnet run, got a guess, found the hypothesis queue full (`MAX_OPEN`), dropped it, and settled the subject for good: money spent, question never asked, subject closed.
- **Why somebody did something is the one fact a house never records, and it is the fact worth having.** The reason behind a seven o'clock habit is the lawn being in full sun until six, or water being metered cheaply after seven, and neither is in any state, statistic or logbook. Asking a model which events are interesting would be a model call per event to decide whether to make a model call per event. `brief.worth_saying`'s rule has more riding on it here: a brief nobody needed is a wasted turn, a question nobody needed is a wasted turn **and** a line of somebody's attention. The two settings once on offer for the budget were low enough to make the feature pointless and high enough that nobody should have been asked.
- **Some questions a house should not ask, and that is a refusal rather than a ranking.** One badly-judged question of that shape costs more trust than every well-judged one earns, and a ranking is a thing that gets tuned. Without the odd-press rule the first press on a newly installed device would be the strangest event in the house every time; a straight subtraction made every late evening the oddest press ever recorded; and a press judged against a shape that included itself came out ordinary.

## Occasions

- **The weather is arithmetic, a calendar is somebody else's text, and an occasion is a fact that expires.** Occasions were the first writer of `expires`, which `retrieval_block` already honoured.

## The memory extractor hook and study sessions

- **The terminal and the chat teach memory, off Claude Code's own `Stop` hook.** Before it, the two faces the most knowledgeable person in the house types into taught nothing. The first cut of the worth-check matched "remember" in the model's canned answer and spent a run on every turn. `test_it_exits_at_once` measured the hook's wait.
- **The memory extractor reads what is new, from somewhere that costs nothing.** A test held the script's isolation settings equal to `engine.isolation_settings()`.
- **The extractor files only what the PERSON said as theirs.** The worth-check always judged the person's words alone, but the pass reads the whole window. `test_the_record_carries_the_six_keys` held the record's shape.
- **A study session runs with the analyst's tool lists, refuses if it cannot read them, and wave 1 of this file claimed both before either was true** (`scripts/brain-learn.sh`). What was written down was "study sessions run read-only"; what shipped passed **no tool flags at all**, so it inherited `/config/.claude/settings.local.json` — Bash, Write, Edit and the whole MCP surface — on a path an automation can reach through the `brain.study` service. The study watcher's `max_turns` was once a field nobody read.

## The deep check's memory probe

- **The deep check's memory probe was the most droppable line anybody could hand the consolidator** (`doctor.MEMORY_FACT_PREFIX`). It read `brAIn deep check marker <epoch> — ignore this line.`, handed to a Claude turn told to merge what it is given into four sections of facts about the HOUSE, to dedupe, and to exclude one-off commands. A working pass was right to drop it, and the stage then reported *"a pass consumed it without writing it down"* — the sentence for a broken memory pipeline — on installs whose memory was working perfectly.
- **That rewrite kept the clause that made it droppable and the verdict it had earned**. 1.49.0's rewrite took out the "ignore this line" and kept a clause stating its subject was about to be deleted, a bare epoch mid-prose and a subject — the fixer helper — the deep check was never actually creating.
- **A drained queue is the proof the memory pipeline ran, and the stage read its silence as a fault** (`doctor.stage_memory`). The probe read "… is a diagnostic entity brAIn creates while checking itself; **it is removed again straight away**", and the consolidator's prompt says "NEVER include secrets, credentials, transient device states, or one-off commands" — a line whose second half states that its subject is about to be deleted is a transient device state written out longhand, so the pass that dropped it was the pass working. The failure ending once left the probe in the inbox, the one ending that had not been given the line that removes it.
- The related hole was named at the time and is still open: **the drain is per pass and the filing decision is per fact, and nothing reconciles them**.
