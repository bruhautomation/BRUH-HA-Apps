    Backups
    
      
    Git-mode backups store incremental history; restoring a commit re-syncs the world from that snapshot. Backups are per-world — switch worlds from the Worlds tab to browse another profile's history.
    
      
    
    
    

    
    
    
      
    Worlds
    
      
    
        Each world is a self-contained server root under /config/minecraft-worlds/<name>/ with its own save files, plugins/ folder, server.properties, ops/whitelist/bans, and backup history. Only one is active at a time.
      
    
      
    
        What's per-world: all gameplay settings (gamemode, difficulty, PVP, world-gen, whitelist, MOTD, …) in this world's server.properties — edit them on the Server Properties tab. Plus save files, plugins on disk, ops/whitelist/bans, and backup history. So one world can be creative and another survival.
    
        What's shared (add-on Configuration tab): install-level only — memory_mb + JVM, server type/version, backups, the plugins: URL list (copied into each world's plugins/ on boot), RCON password, and Bedrock/Geyser.
      
    
      
    
        Switching is a one-click operation (since 1.2.9): hit Switch below and the add-on restarts itself so the new world's plugins, world files, and server.properties are loaded. The panel is unreachable for ~30 s while the container comes back up — refresh after that. The header's Restart button only kicks the JVM, which is faster but does NOT re-point the world symlink, so it won't switch worlds on its own.
