Welcome to BRUH Minecraft

A short walk-through to spin up your first world. You can change anything later from the panel or the add-on's Configuration tab.

Step 1 of 9

1. Accept the Minecraft EULA

Mojang requires every server operator to accept their End User Licence Agreement before running a server. This is a one-time legal step, not a config choice — we won't store it anywhere except the add-on's options.

2. Choose your server software

This is the program that actually hosts the world. They all play Minecraft, but they differ on performance, plugin/mod support, and compatibility with Bedrock cross-play. Paper is the right answer for ~99% of home servers.

3. Who's joining your server?

Two related choices — they decide how players sign in and which devices can connect at all. Both editable per-world later from the Server Properties tab.

Authentication mode

Bedrock cross-play (iOS, Android, Xbox, Switch, PS, Win10/11)

Bedrock players run a different version of Minecraft than the Java server. Geyser + Floodgate are plugins that translate between the two so Java and Bedrock players share one world. Only works with Paper / Purpur / Folia (your earlier pick), and the add-on installs both for you.

4. Your first world — basics

Per-world settings stored in this world's server.properties. You can have multiple worlds with different settings — switch between them from the Worlds tab.

1–32 characters; letters, digits, _ and -. The folder name on disk under /config/minecraft-worlds/.
Determines terrain generation. Blank = random. Only matters when this world is first generated.

5. Players & access

How many players, who's allowed in, and how PvP behaves. All per-world server.properties keys — editable later from the Server Properties tab.

Hard cap on concurrent connections. Vanilla default is 20. Bump it for a community server; each player adds RAM/CPU load.
Around world spawn, only OPs can break or place blocks. 16 is vanilla default. Set to 0 if you want anyone to build at spawn — common on small family servers.

6. Performance

We detect your host's RAM and propose a heap size + view/sim distance, then preview the expected player capacity. All tunable later from the Dashboard's Tune for my hardware button and the per-world Server Properties tab.

Detecting host hardware…
JVM heap (both -Xms and -Xmx). 1–2 GB for a few friends; 4–6 GB for a busy plugin server; 8+ GB for big modpacks.
Chunks (16-block squares) sent around each player. Higher = farther sightlines, more RAM/CPU.
Chunks actively ticked (mobs, redstone, crops). The bigger TPS lever — drop this first if the server feels slow.

7. Plugins

Curated, well-known Bukkit plugins the add-on can install automatically. Each toggle resolves the latest Paper-compatible build from Modrinth on every boot. Available only for Paper / Purpur / Folia — skipped on Vanilla/Fabric/Forge.

Essential — leave on

ViaVersion + ViaBackwards always on Protocol bridges so clients on a different Minecraft version than your server can still connect — hides the gap between a Mojang release and the matching Paper build (the "Outdated server!" / "This server does not support Java Edition X.Y" kicks). No gameplay impact. Toggleable in the Configuration tab if you really need to disable, but almost no one wants to.

Optional — pick what you want

8. Backups & maintenance

Sensible defaults are picked for you — most home servers don't need to change these. Worth a one-screen confirmation that the safety nets are running.

How often the background watcher snapshots the active world. 60 (hourly) is the default. Lower = more frequent safety net + more disk churn.
Older snapshots are pruned. 48 at hourly cadence ≈ 2 days of history. Git mode (default) only stores deltas, so disk use is small.

Auto-update of the server jar, crash auto-restart (rate-limited), and the Home Assistant integration (sensors + services) are on by default and don't need configuration. You can disable any of them from the Configuration tab later.

9. Review & start

Here's what we'll set up. Start the server writes everything and restarts the add-on. The panel will be unreachable for ~30 seconds while the server boots.

All of this is editable later — the panel's Server Properties, Plugins, Worlds, and Backups tabs cover everything you can change here.

    Backups
    
      
    Git-mode backups store incremental history; restoring a commit re-syncs the world from that snapshot. Backups are per-world — switch worlds from the Worlds tab to browse another profile's history.
    
      
    
    
    

    
    
    
      
    Worlds
    
      
    
        Each world is a self-contained server root under /config/minecraft-worlds/<name>/ with its own save files, plugins/ folder, server.properties, ops/whitelist/bans, and backup history. Only one is active at a time.
      
    
      
    
        What's per-world: all gameplay settings (gamemode, difficulty, PVP, world-gen, whitelist, MOTD, …) in this world's server.properties — edit them on the Server Properties tab. Plus save files, plugins on disk, ops/whitelist/bans, and backup history. So one world can be creative and another survival.
    
        What's shared (add-on Configuration tab): install-level only — memory_mb + JVM, server type/version, backups, the plugins: URL list (copied into each world's plugins/ on boot), RCON password, and Bedrock/Geyser.
      
    
      
    
        Switching is a one-click operation (since 1.2.9): hit Switch below and the add-on restarts itself so the new world's plugins, world files, and server.properties are loaded. The panel is unreachable for ~30 s while the container comes back up — refresh after that. The header's Restart button only kicks the JVM, which is faster but does NOT re-point the world symlink, so it won't switch worlds on its own.

    Featured worlds
    
      
    
        One-click, fully server-side installs of large community worlds — the world save and its datapacks are downloaded onto the server, so anyone (including iPad / iPhone players over Geyser) can join and explore with zero local installs. The resource pack is hosted for Java players and auto-converted to a Bedrock pack that Geyser pushes to phones/tablets on join (best-effort — custom 3D models can't convert). Installing stages a new world; your current world is untouched until you Switch to it above. Switching pins the server to the version the world needs and turns Bedrock support on.

    Resource Packs
    
      
    
        Drop a Minecraft resource pack .zip here and the add-on hosts it for you. Use Apply to active world to plug the URL + SHA-1 directly into the active world's server.properties — no copy-pasting hashes. Packs are global; one pack can serve every world.
      
    
      
    
        How clients fetch the pack: the add-on serves it at
        http://<your-HA-host>:8099/pack/<filename> on your LAN. The
        Apply button fills that URL in for you using the host you're loading this panel from.
